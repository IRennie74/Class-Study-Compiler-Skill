Solving method — "fill in the C" for straight-line arithmetic

  1. Register map. From the prototype, write x → %rdi, y → %rsi, z → %rdx (then %rcx, %r8, %r9).
  2. Annotate every line. Next to each instruction, write the new value of the destination (the second operand) as an expression in the original variables. Use these translations:
    InstructionWrite
    leaq D(a,b,S), dd = D + a + S·b
    subq s, dd = d − s (reversed from how it reads)
    salq k, dd = d · 2k
    sarq k, d / shrq k, dd = d >> k (signed / unsigned)
    notq d / negq dd = ~d / d = −d
    xorq r, rr = 0
  3. Track register reuse. When a register is overwritten, its old meaning is gone. Cross it out in your map.
  4. Match to the blanks. The C temporaries (t1, t2, …) are usually the values after particular lines. The compiler may merge two C lines into one leaq, or reorder independent ones.
  5. Verify with numbers. Pick x = 1, y = 2, z = 3, run both the assembly (on your annotations) and your C, and check that they agree. It takes 30 seconds and catches most sign and order mistakes.

How to show your work: model answer (Practice Problem 3.10 style)

Register map:  x → %rdi   y → %rsi   z → %rdx

Line  Instruction        Destination ← new value              C name
1     orq  %rsi, %rdi    rdi ← x | y                          t1
2     sarq $3, %rdi      rdi ← t1 >> 3   (arith, x is signed)  t2
3     notq %rdi          rdi ← ~t2                            t3
4     movq %rdx, %rax    rax ← z
5     subq %rdi, %rax    rax ← z − t3     (dest − src!)        t4  → returned

Answer:   long t1 = x | y;   long t2 = t1 >> 3;   long t3 = ~t2;   long t4 = z - t3;

Check (x=1, y=2, z=3): t1 = 3, t2 = 0, t3 = −1, t4 = 3 − (−1) = 4.
          The assembly gives the same: rdi: 3 → 0 → −1; rax: 3 → 4 ✓

For instruction-effect tables (3.8 style), write: dest = (address calc) ; old value op source = new value. For example: "subq %rdx,8(%rax): dest = 0x100 + 8 = 0x108; 0xAB − 3 = 0xA8".

2.3 
map: x → rdi, y → rsi, z → rdx
1 leaq (%rdi,%rdi,4),%rax   rax ← 5x
2 subq %rsi,%rax            rax ← 5x − y              t1
3 andq %rdx,%rax            rax ← t1 & z              t2
4 salq $3,%rdx              rdx ← z << 3  (= 8z)       t3   (z's old meaning is gone)
5 subq %rax,%rdx            rdx ← t3 − t2             t4
6 movq %rdx,%rax            return t4

Answer: t1 = 5*x - y;  t2 = t1 & z;  t3 = z << 3;  (or z*8)  t4 = t3 - t2;
Check x=1,y=2,z=3: t1 = 3, t2 = 3&3 = 3, t3 = 24, t4 = 21.  asm: rax 5 → 3 → 3; rdx 24 → 21 ✓

2.6 
1-2  rax ← a ^ b                 t1
3    rdx ← t1 + 8·t1 = 9·t1      t2 = t1 * 9
4    rax ← t1 >> 2  (shr → unsigned/logical shift of t1)
5    rax ← −(t1 >> 2)            t3 = -(t1 >> 2)
6    rax ← t3 + t2               return t2 + t3;
Answer: t2 = t1 * 9;  t3 = -(t1 >> 2);  return t2 + t3;
Note: shrq is a LOGICAL shift because the values are unsigned. For a signed long the compiler
uses sarq, so the shift instruction tells you the type.

(a) leaq (%rdi,%rsi),%rax ; leaq -4(%rdx),%rcx ; imulq %rcx,%rax ; ret
    (or: movq %rdi,%rax ; addq %rsi,%rax ; movq %rdx,%rcx ; subq $4,%rcx ; imulq %rcx,%rax)

2.10 
(a) xorl %eax,%eax (or xorq %rax,%rax) sets rax = 0. It is shorter to encode than movq $0,%rax.
(b) leaq does not touch the flags and can add three things (D + a + S·b) into any destination
    in one instruction. add needs dest = one of the sources.
(c) Two's complement: addition, subtraction and multiplication (low 64 bits) give the same bit
    pattern for signed and unsigned values. Only shifts right, comparisons and division differ.
(d) 3 → (r,r,2); 5 → (r,r,4); 9 → (r,r,8). These are the only 1-instruction leaq multipliers
    (plus 2, 4, 8 via (,r,S), and 1).
  • I annotate every line before writing C.
  • I always write sub s,d as d − s.
  • I can turn any leaq into an algebra expression.
  • I check my answer with small numbers.
  • I know the difference between notq and negq, and between sarq and shrq.
