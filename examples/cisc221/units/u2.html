M1leaq as algebra

How it's asked
%rax holds x and %rcx holds y. Give a formula for the value stored in %rdx by each instruction: (a) leaq 6(%rax),%rdx (b) leaq (%rax,%rcx,4),%rdx (c) leaq 7(%rax,%rax,8),%rdx (d) leaq 0xA(,%rcx,4),%rdx
What you're looking at

leaq is an instruction ("load effective address") that computes a number from the pattern D(Rb,Ri,S). Here %rax holds x and %rcx holds y, and each result goes into %rdx. The question asks you to write that number as algebra in x and y.

The answer, written exactly like this
          D + Rb + S·Ri
(a)       6 + x              = x + 6
(b)       0 + x + 4·y        = x + 4y
(c)       7 + x + 8·x        = 9x + 7
(d)       10 + 0 + 4·y       = 4y + 10        (0xA = 10)
How it works

leaq means load effective address. It computes the address that D(Rb,Ri,S) describes (D + Rb + S·Ri) and stores that number in the destination. It never reads memory and it does not change the condition codes.

It was designed for pointers: p = &a[i] becomes leaq (%rdi,%rsi,4),%rax. But the compiler also uses it as a fast calculator for anything of the form x + k·y + c with k ∈ {1,2,4,8}, because one leaq does an add, a scale and a constant at once. leaq (%rdi,%rdi,2) = x + 2x = 3x. That is how it multiplies by small constants (M7).

Compare movq 8(%rax),%rdx, which reads memory at %rax + 8, with leaq 8(%rax),%rdx, which just computes %rax + 8. Mixing these up is the most common trap.

Every time, do this
  1. Write the template D + Rb + S·Ri.
  2. Substitute the variables (missing parts = 0; convert hex D).
  3. Simplify into one algebra expression.

M2Instruction effects table

How it's asked
M[0x100] = 0xFF, M[0x108] = 0xAB, M[0x110] = 0x13, M[0x118] = 0x11; %rax = 0x100, %rcx = 0x1, %rdx = 0x3. For each instruction (each starts from the original state), give the destination and its new value: addq %rcx,(%rax) · subq %rdx,8(%rax) · imulq $16,(%rax,%rdx,8) · decq %rcx
What you're looking at

The two tables give memory and register contents before anything runs. Each instruction then changes one place: its destination, the last operand. "Each starts from the original state" means the rows are independent: don't carry results from one row to the next. You give where the result goes, and its new value.

The answer, written exactly like this
Instruction                Destination               Old  op  source    New value
addq %rcx,(%rax)           M[0x100]                  0xFF + 0x1         0x100
subq %rdx,8(%rax)          M[0x100+8 = 0x108]        0xAB − 0x3         0xA8
imulq $16,(%rax,%rdx,8)    M[0x100+8·3 = 0x118]      0x11 · 16          0x110
decq %rcx                  %rcx                      0x1 − 1            0x0
How it works

Two-operand arithmetic in AT&T syntax is op Source, Dest and means Dest = Dest op Source: the second operand is both an input and the place the result goes. So subq %rdx,8(%rax) means "M[0x108] = M[0x108] − %rdx". It does not subtract the memory from the register.

When the destination is memory, the CPU reads that memory, does the operation and writes the result back, all in one instruction. One-operand instructions (incq, decq, negq, notq) change their only operand.

Hex arithmetic tip: multiplying by 16 shifts one hex digit left (0x11 · 16 = 0x110). Subtracting a small number from a value ending in a digit A–F means counting down in hex (0xAB − 3 = 0xA8).

Every time, do this
  1. The destination is the 2nd operand. If it is memory, compute its address.
  2. Write: old value, op, source.
  3. Compute the new value in hex. Every row starts from the original state.

M3Reverse straight-line code → C

How it's asked
Fill in the C. Here x is in %rdi, y in %rsi and z in %rdx. 
long arith(long x, long y, long z) {
  long t1 = ______;
  long t2 = ______;
  long t3 = ______;
  long t4 = ______;
  return t4;
}
arith:
  leaq  (%rdi,%rsi), %rax
  addq  %rdx, %rax
  leaq  (%rsi,%rsi,2), %rdx
  salq  $4, %rdx
  imulq %rdx, %rax
  ret
What you're looking at

Left: C code where the right-hand sides are hidden (______). Right: the assembly the compiler made from the complete C. The comment line tells you x, y, z are in %rdi, %rsi, %rdx. t1 to t4 are temporary variables; you find what each one equals by reading the assembly.

The answer, written exactly like this
Map: x → %rdi   y → %rsi   z → %rdx
Line                     Destination ← new value         Name
leaq (%rdi,%rsi),%rax    rax ← x + y                     t1
addq %rdx,%rax           rax ← t1 + z                    t2
leaq (%rsi,%rsi,2),%rdx  rdx ← 3y        (z is gone now)
salq $4,%rdx             rdx ← 3y · 16 = 48y             t3
imulq %rdx,%rax          rax ← t2 · t3                   t4 → returned

long t1 = x + y;  long t2 = t1 + z;  long t3 = y * 48;  long t4 = t2 * t3;
Check x=1, y=2, z=3:  t1=3, t2=6, t3=96, t4=576.  asm: rax 3→6, rdx 6→96, rax 576 ✓
How it works

Compiled code is a list of tiny steps, and each step changes exactly one place: its destination. If you write down what every destination holds after every line, in terms of the original variables, the C appears by itself.

Three things make this harder than it looks:

  • Registers get reused. Above, %rdx starts as z, but once z has been used, the compiler overwrites %rdx with 3y. Always track what a register holds now.
  • The compiler optimises. It turns y*48 into a leaq (3y) plus a shift (·16), and it may merge two C lines into one leaq (the lecture's x+4 folded into leaq 4(%rdi,%rdx)).
  • Operand order. subq s,d is d − s. sal k multiplies by 2k.

The temporaries t1, t2 … in the template are the values after particular lines. Match them by meaning, not by line number.

Every time, do this
  1. Write the register map.
  2. Fill in a "Destination ← new value" column for every line.
  3. Match the values to the blanks.
  4. Check with x=1, y=2, z=3 (M4).

M4Verify with numbers

How it's asked
(Never asked on its own, but it is what makes your M3 answers correct.) Someone answered the arith question above with t3 = y * 16. Use numbers to show whether that is right.
What you're looking at

This card isn't a separate test question. It's the habit that checks any "fill in the C" answer: plug small numbers into your answer and into the assembly and compare.

The answer, written exactly like this
Pick x = 1, y = 2, z = 3.
Assembly:  rdx = 3·2 = 6 → 6 << 4 = 96        so t3 = 96
Proposed:  y * 16 = 32                        32 ≠ 96 → wrong
Correct:   y * 48 = 96 ✓   (the leaq made 3y BEFORE the shift)
How it works

If two expressions are equal for all inputs, they are equal for one easy input. So after you write your C, run it by hand with small numbers, and run your annotated assembly with the same numbers. If they agree, you are almost certainly right. If they don't, the first line where they differ shows the bug.

Use distinct small values (1, 2, 3) so that mixed-up variables show up (x + y ≠ x + z). Avoid 0 and 1 for multipliers, because they hide mistakes (y·0 = 0 whatever the constant). Writing the check line on the test also shows the grader your reasoning.

Every time, do this
  1. Choose x=1, y=2, z=3 (or similar distinct values).
  2. Evaluate your C and the annotated assembly.
  3. Write "Check: … ✓" under your answer.

M5Signed vs. unsigned clues; not vs. neg

How it's asked
Fill in: t2 = t1 ___ 3; t3 = ___t2; given sarq $3,%rdi then notq %rdi, where t1 is a long. What would change if the code used shrq and negq?
What you're looking at

Two blanks to fill in from the instructions: sarq $3 is "shift right by 3", and notq is a bit-flipping instruction. The question also asks how the answer would change with the similar instructions shrq and negq.

The answer, written exactly like this
sarq $3 → t2 = t1 >> 3      arithmetic shift: t1 is a signed long
notq    → t3 = ~t2          bitwise NOT
With shrq: the value being shifted would be unsigned (a logical shift, filling with 0s).
With negq: t3 = -t2 (two's-complement negation), not ~t2.
How it works

C has a single >> operator, but the machine has two right shifts:

  • sar (arithmetic) copies the sign bit into the vacated bits. For signed numbers it divides by 2k (rounding down): −8 >> 1 = −4.
  • shr (logical) fills with 0. It is correct for unsigned numbers.

The compiler picks sar for signed types and shr for unsigned types, so the instruction tells you the type. Left shifts are the same either way (sal = shl).

not flips every bit (C's ~). neg computes −x, which in two's complement is ~x + 1. They differ by 1: ~5 = −6, but −5 = −5.

Every time, do this
  1. sar → signed >>; shr → unsigned >>. Note the type.
  2. not → ~; neg → −.

M6C → assembly for expressions

How it's asked
Write the assembly for long f(long x, long y) { return (x - y) * (y + 3); }.
What you're looking at

A complete C function is given, and you write the assembly. (x - y) * (y + 3) must be computed using instructions, with the inputs in %rdi/%rsi and the result in %rax.

The answer, written exactly like this
f:                          # x in %rdi, y in %rsi
  movq  %rdi, %rax          # rax = x
  subq  %rsi, %rax          # rax = x − y
  leaq  3(%rsi), %rdx       # rdx = y + 3
  imulq %rdx, %rax          # rax = (x − y)(y + 3)
  ret                       # result in %rax
How it works

To write assembly for an expression, think about where the result must end up: the return value always goes in %rax. Build the result there, using other caller-saved registers (%rdx, %rcx, %r8…) as scratch space for sub-expressions.

  • Two-operand instructions overwrite their destination, so copy first (movq %rdi,%rax) if you still need the original.
  • Use leaq to compute "register + constant" or "a + k·b" into a new register without destroying the inputs.
  • Keep the sub order right: x − y is movq x,%rax ; subq y,%rax.
  • Choose sar for signed >> and shr for unsigned (M5).

There are several correct answers. Graders accept any that compute the right value, as long as each line is commented.

Every time, do this
  1. Write the register map; the result goes in %rax.
  2. Compute each sub-expression, commenting each line with its C meaning.
  3. Combine the results into %rax, then ret.

M7Multiply by a constant without imul

How it's asked
Using only leaq, shifts, add and sub, compute (a) 12x and (b) 7x, with x in %rdi and the result in %rax.
What you're looking at

You must produce 12·x and 7·x using only cheap instructions (no multiply instruction). x starts in %rdi; put the answer in %rax.

The answer, written exactly like this
(a) 12 = 3 · 4
    leaq (%rdi,%rdi,2), %rax    # 3x
    salq $2, %rax               # 3x · 4 = 12x
(b) 7 = 8 − 1
    leaq 0(,%rdi,8), %rax       # 8x
    subq %rdi, %rax             # 8x − x = 7x
How it works

Multiplication used to be slow, and compilers still prefer cheaper instructions for known constants. The tools are:

  • leaq multiplies by 2, 3, 4, 5, 8 or 9 in one step: (r,r,S) = (S+1)·r and (,r,S) = S·r.
  • salq $k multiplies by 2k.
  • add/sub combine the results: 7x = 8x − x, and 10x = 5x + 5x.

So factor the constant into (a leaq multiplier) × (a power of 2), or write it as a sum or difference of easy pieces. This is exactly the lecture's m12 example (x*12 → leaq 3x, then salq $2). The same pattern appears inside array code (L14), where 7i is built with leaq and sub.

Every time, do this
  1. Factor: constant = {2,3,4,5,8,9} × 2k, or a difference like 8 − 1.
  2. leaq first, then salq, then add/sub.
  3. Comment every line with the multiple it now holds.

M8Short-answer "why" questions

How it's asked
(Practice Problem 3.11 style) Code often contains xorq %rdx,%rdx even where the C has no XOR. (A) What does it do? (B) What is the straightforward alternative? (C) Why does the compiler prefer the XOR?
What you're looking at

xorq %rdx,%rdx is an XOR instruction with the same register twice. The question asks what it accomplishes, the obvious alternative, and why the compiler prefers it: a "why" question answered in sentences.

The answer, written exactly like this
(A) x ^ x = 0 for every x, so it sets %rdx to 0 (it implements rdx = 0).
(B) movq $0, %rdx
(C) The XOR version is shorter to encode (3 bytes vs 7), so it is smaller and fast.
    (xorl %edx,%edx is only 2 bytes and also clears the upper half.)
How it works

"Why" questions want a fact plus a reason. The common ones in this unit:

  • xor r,r: zeroes a register, with a shorter encoding than mov $0.
  • Why leaq for arithmetic? It adds up to three terms (D + a + S·b) into any register in one instruction and leaves the condition codes alone.
  • Why is there one add for signed and unsigned? In two's complement, addition, subtraction and multiplication (low bits) give the same bit pattern either way. Only right shifts, comparisons and division depend on the interpretation.
  • Why only scales 1, 2, 4, 8? They are the data-type sizes, and the encoding has 2 bits for the scale.
Every time, do this
  1. State the fact in one line.
  2. Give the reason ("because …").
  3. Add a concrete example if you can.

(b) leaq does not touch the flags and can add three things (D + a + S·b) into any destination
