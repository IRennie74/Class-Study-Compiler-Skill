M1Toolchain commands

How it's asked
The command gcc -Og -o app main.c helper.c is run. List, in order, every tool that runs and the files it produces. Then say what objdump -d app does.
The answer, written exactly like this
Stage        Tool        Input               Output
1 compile    compiler    main.c, helper.c    main.s, helper.s  (assembly text)
2 assemble   assembler   main.s, helper.s    main.o, helper.o  (machine code)
3 link       linker      main.o, helper.o    app               (executable)
                         + libraries (.a)
(the .s and .o files are temporary: gcc deletes them because no stop flag was given)
objdump -d app: the disassembler reads the bytes of app and prints the assembly.
                It creates no file.
How it works

A C program goes through four tools before it can run. gcc is not one tool: it is a driver that runs the others for you.

  calc.c ──compiler──▶ calc.s ──assembler──▶ calc.o ──linker──▶ calc
  (C text)            (assembly text)       (machine code,      (executable)
                                             addresses missing)   ▲ libraries (.a)
  • Compiler (gcc -S): turns C into assembly text. This is where register and instruction choices are made. -Og is the optimisation level, chosen to give readable assembly.
  • Assembler (as, or gcc -c): turns each assembly line into bytes. In the lecture's sumstore example, the instructions are 1, 3 or 5 bytes each, 14 bytes in total. The object file is "nearly complete": calls to functions in other files still have placeholder addresses.
  • Linker (ld, or plain gcc with .o inputs): joins all the .o files and the library code (for example printf) and fills in those missing addresses. Some libraries are linked dynamically instead, when the program starts.
  • Disassembler (objdump -d, or disassemble in gdb): goes backwards, from bytes to an "approximate rendition" of the assembly. It works on .o files and executables.

Reading the flags: gcc starts from whatever stage the input file is at. -S means stop after compiling, -c means stop after assembling, and with neither flag it goes all the way. -o name only chooses the output file name.

Every time, do this
  1. Look at the input file type (.c, .s, .o, executable).
  2. Look for a stop flag (-S, -c, or none).
  3. Write one row per stage, from the input's stage to the stop point: tool and output file.

M2ISA vs. microarchitecture

How it's asked
Classify each item as part of the ISA or the microarchitecture: (a) the leaq instruction exists; (b) the processor has a 1 MB L2 cache; (c) there are 16 integer registers; (d) the chip runs at 4.0 GHz.
The answer, written exactly like this
Item                 Visible to an assembly programmer?   Answer
(a) leaq exists      yes: you can write it                ISA
(b) 1 MB L2 cache    no: it only changes speed            microarchitecture
(c) 16 registers     yes: you name them in code           ISA
(d) 4.0 GHz clock    no: it only changes speed            microarchitecture
How it works

The ISA (instruction set architecture, or "architecture") is the contract between software and hardware. It is everything you need to know to write correct assembly or machine code: the instructions, the registers, the condition codes, and how memory is addressed. x86-64 is an ISA, and so is ARM.

The microarchitecture is how one particular chip fulfils that contract: cache sizes, clock frequency, pipelines, the number of cores. An Intel chip and an AMD chip can have very different microarchitectures, yet both run the same x86-64 program, because they share the ISA. An ARM phone has a different ISA, so the program must be recompiled.

The chef analogy from the lecture: the recipe language is the ISA. Whether the kitchen has a big countertop (cache) or a fast stove (clock) is the microarchitecture. It changes how fast the meal is made, not what the meal is.

Related fact: x86 is a CISC (complex instruction set computer), with many instructions and formats. ARM is closer to RISC (reduced instruction set).

Every time, do this
  1. Ask: "Could I see or use this from assembly code?"
  2. Yes → ISA. No (it only changes speed or size) → microarchitecture.
  3. Write the reason next to each answer.

M3Register names

How it's asked
Give the 4-byte, 2-byte and 1-byte names of %rcx, %rdi and %r13.
The answer, written exactly like this
Register  Group             4 bytes   2 bytes   1 byte
%rcx      a/b/c/d           %ecx      %cx       %cl
%rdi      si/di/sp/bp       %edi      %di       %dil
%r13      r8–r15            %r13d     %r13w     %r13b
How it works

Each of the 16 registers holds 8 bytes. You can also use only its low 4, 2 or 1 bytes, and each smaller piece has its own name. They are not separate registers: they are nested parts of the same one.

%rcx │■■■■■■■■│   all 8 bytes
%ecx │    ■■■■│   low 4 bytes
%cx  │      ■■│   low 2 bytes
%cl  │       ■│   lowest byte

The names follow three patterns, which come from history: the 16-bit chips had %ax with low byte %al, the 32-bit chips added e for "extended" (%eax), and the 64-bit chips added r (%rax) plus eight new registers, %r8–%r15.

Group8421
rax, rbx, rcx, rdx%rbx%ebx%bx%bl (x→l)
rsi, rdi, rsp, rbp%rsi%esi%si%sil (add l)
r8 … r15%r9%r9d%r9w%r9b

The names matter because the name you use decides how many bytes an instruction reads or writes (see M4 and M6). A made-up name like %sl is an assembler error (Practice Problem 3.3).

Every time, do this
  1. Write the register's group next to it.
  2. Apply that group's pattern for 4, 2 and 1 bytes.
  3. Double-check any 1-byte name: %sil, %dil, %spl and %bpl all end in l.

M4Writing part of a register

How it's asked
%rax = 0x0123456789ABCDEF. The lines run in order. Give %rax after each: (a) movb $0x11,%al (b) movw $0x2233,%ax (c) movl $0x44,%eax (d) movb $0x80,%al; then (e) movsbq %al,%rdx, giving %rdx.
The answer, written exactly like this
(a) movb $0x11,%al      0x0123456789ABCD11   only byte 0 changes
(b) movw $0x2233,%ax    0x0123456789AB2233   only bytes 0–1 change
(c) movl $0x44,%eax     0x0000000000000044   4-byte write → upper 4 bytes become 0
(d) movb $0x80,%al      0x0000000000000080
(e) movsbq %al,%rdx     %rdx = 0xFFFFFFFFFFFFFF80
                        0x80 = 1000 0000₂ → sign bit 1 → fill with 1s (−128 stays −128)
How it works

The rule: a 1-byte or 2-byte write changes only those bytes. A 4-byte write also sets the upper 4 bytes to zero. x86-64 was designed this way so that 32-bit code works cleanly. It is also why the compiler writes movl $0,%eax to clear all of %rax, and why no movzlq instruction exists: movl already zero-extends.

Extending means copying a small value into a bigger space without changing its meaning:

  • Zero-extension (movz__) fills the new bytes with 0. That keeps an unsigned value the same: 0x80 → 0x0000000000000080 = 128.
  • Sign-extension (movs__) fills the new bytes with copies of the sign bit (the top bit). That keeps a signed two's-complement value the same: 0x80 = −128 → 0xFFFFFFFFFFFFFF80 = −128.

The two letters after movz/movs are the from and to sizes: movsbq = sign-extend a byte to a quad.

Every time, do this
  1. Write all 16 hex digits of the starting value.
  2. For each line: 1 or 2 bytes → replace only those digits. 4 bytes → replace the low 8 digits and zero the high 8.
  3. movs: look at the top bit of the source (hex digit 8–F means 1 → fill with F). movz: fill with 0.

M5Operand values

How it's asked
Memory: M[0x300] = 0xA, M[0x308] = 0xB, M[0x310] = 0xC. Registers: %rax = 0x300, %rbx = 0x8, %rcx = 0x2. Give the value of each operand: %rbx, $0x308, 0x310, (%rax), 8(%rax), (%rax,%rbx), 8(%rax,%rcx,4), 752(,%rbx,2).
The answer, written exactly like this
Operand           Kind        Address work                          Value
%rbx              register    —                                     0x8
$0x308            immediate   — (no memory read)                    0x308
0x310             memory      absolute address 0x310                0xC
(%rax)            memory      0x300                                 0xA
8(%rax)           memory      0x300 + 8 = 0x308                     0xB
(%rax,%rbx)       memory      0x300 + 0x8 = 0x308                   0xB
8(%rax,%rcx,4)    memory      8 + 0x300 + 4·2 = 0x310               0xC
752(,%rbx,2)      memory      752 = 0x2F0; 0x2F0 + 2·8 = 0x300      0xA
How it works

An operand is where an instruction gets (or puts) a value. There are exactly three kinds:

  • Immediate $c: the constant itself, built into the instruction. Nothing is looked up.
  • Register %r: the value stored in that register.
  • Memory: the value at an address in memory. A bare number like 0x310 is an absolute address. Anything with parentheses computes an address.

The general memory form is D(Rb,Ri,S), which means address = D + Rb + S·Ri:

  • D: a constant displacement. Rb: the base register (often a pointer).
  • Ri: the index register (any register except %rsp). S: the scale, only 1, 2, 4 or 8.

Why this shape? It is exactly what C needs. *p → (%rdi). A struct field p->f → 8(%rdi). An array element a[i] of 4-byte ints → (%rdi,%rsi,4), i.e. base + i × element size. The scales 1, 2, 4 and 8 are the sizes of char, short, int and long/pointer.

Two traps: a displacement without 0x is decimal (752 = 0x2F0). And $0x308 (the number) is not the same as 0x308 (the memory at that address).

Every time, do this
  1. Classify: $ → immediate; %reg → register; otherwise memory.
  2. Memory: convert any decimal displacement to hex, then compute D + Rb + S·Ri.
  3. Look the address up in the memory table and write the value.

M6Instruction suffix

How it's asked
Fill in the suffix: mov__ %ecx,(%rdx) · mov__ (%rsp),%r9 · mov__ $5,%sil · mov__ %bp,8(%rax).
The answer, written exactly like this
movl %ecx,(%rdx)      %ecx is 4 bytes → l
movq (%rsp),%r9       %r9 is 8 bytes → q          (%rsp in ( ) is just an address)
movb $5,%sil          %sil is 1 byte → b
movw %bp,8(%rax)      %bp is 2 bytes → w
How it works

Every data instruction needs to know how many bytes to move. AT&T syntax puts that in a one-letter suffix:

SuffixNameBytesC type
bbyte1char
wword2short
llong word4int
qquad word8long, pointer

("Word" means 2 bytes because the original 8086 was a 16-bit machine.)

The size comes from the data register, because a register name tells you its size (M3). A memory operand like (%rdx) has no size of its own, and the register inside the parentheses only supplies an address, which is always 64-bit. If an instruction moves an immediate to memory (mov $5,(%rax)), nothing implies a size, so you must state the suffix explicitly.

Every time, do this
  1. Cover up anything inside parentheses.
  2. Find the remaining register and its size.
  3. Write the suffix and the reason ("%ecx is 4 bytes → l").

M7What's wrong with this instruction?

How it's asked
Each line causes an assembler error. Explain why: movq (%rdi),8(%rdi) · movl $7,%rax · movw $0x10,(%eax) · movq %rax,(%rdi,%rsp,2) · movb %dl,$1.
The answer, written exactly like this
movq (%rdi),8(%rdi)        both operands are memory (memory-to-memory is not allowed)
movl $7,%rax               suffix l (4 bytes) does not match %rax (8 bytes)
movw $0x10,(%eax)          %eax is 32-bit: cannot be an address register (need 64-bit)
movq %rax,(%rdi,%rsp,2)    %rsp cannot be the index register
movb %dl,$1                an immediate cannot be a destination
How it works

Each rule exists because of how instructions are encoded in bytes:

  • At most one memory operand. The encoding has room to describe only one memory address, so copying memory to memory takes two instructions, going through a register.
  • An immediate is not a location. It is a constant inside the instruction, so you cannot store into it.
  • Sizes must agree. The suffix and the register name both state a size, and they must match. A register name that doesn't exist (%sl) is also an error.
  • Addresses are 64-bit on x86-64, so a register used to form an address must be a 64-bit one (%rax, not %eax).
  • %rsp cannot be the index, because the encoding reserves that slot to mean "no index".
  • The scale is a 2-bit field, so only 1, 2, 4 and 8 can be encoded.
Every time, do this
  1. Go through this checklist in order: two memory operands? immediate destination? suffix ≠ register size? register exists? 32-bit address register? %rsp as index? scale ∉ {1,2,4,8}?
  2. Write the first rule that is broken, in one short sentence.

M8Cast moves *dp = (dest_t)*sp

How it's asked
src_t *sp is in %rdi and dest_t *dp is in %rsi. Give the two instructions for *dp = (dest_t)*sp; using %rax (or part of it): (a) short → int (b) unsigned char → int (c) long → char.
The answer, written exactly like this
(a) short → int           movswl (%rdi),%eax ; movl %eax,(%rsi)
                          wider + signed source → sign-extend
(b) unsigned char → int   movzbl (%rdi),%eax ; movl %eax,(%rsi)
                          wider + unsigned source → zero-extend
(c) long → char           movq (%rdi),%rax   ; movb %al,(%rsi)
                          narrower → load all, store the low byte
How it works

A C cast between integer types does one of three things, decided by the sizes:

  • Wider destination: the value must stay the same number. For a signed source that means sign-extension (M4), so −1 stays −1. For an unsigned source it means zero-extension, so 255 stays 255. The source type decides, never the destination: char → unsigned still uses movsbl.
  • Narrower destination: C truncates, keeping only the low bytes. Load at the source's size, then store the small register part (%al, %ax, %eax).
  • Same size: just copy with plain mov. The bits don't change; only how C interprets them does.

The instruction name tells you everything: movs/movz + from-size + to-size (movzbl = zero-extend byte to long). unsigned → long is just movl then movq, because a 4-byte write already zeroes the top half.

Every time, do this
  1. Compare the sizes: wider, narrower or the same?
  2. Wider: s or z according to the source's signedness, then the from/to letters. Store at the destination size.
  3. Narrower: load at the source size, store the destination-sized part of the register.

M9Move traces and assembly → C

How it's asked
void rotate(long *a, long *b), with a in %rdi and b in %rsi, compiles to the code below. Write the C. 
movq (%rdi), %rax
movq (%rsi), %rdx
movq %rdx, (%rdi)
addq %rax, %rdx
movq %rdx, (%rsi)
ret
The answer, written exactly like this
Map: a → %rdi, b → %rsi
Line                   Meaning
movq (%rdi),%rax       x = *a
movq (%rsi),%rdx       y = *b
movq %rdx,(%rdi)       *a = y
addq %rax,%rdx         y = y + x
movq %rdx,(%rsi)       *b = y          (= old *a + old *b)

void rotate(long *a, long *b) { long x = *a; long y = *b; *a = y; *b = x + y; }
How it works

Assembly has no variables, only registers and memory. To turn it back into C, give each register a meaning:

  • A register that holds a parameter is that parameter (%rdi = 1st, %rsi = 2nd, %rdx = 3rd…).
  • Parentheses mean dereference: (%rdi) is *a, and 8(%rdi) is a[1] for longs (8 bytes = 1 element).
  • A load (memory → register) creates a local variable. A store (register → memory) is an assignment through a pointer.

Compiled code usually loads everything first and then stores, because the compiler must read the old values before overwriting them. A state table (one column per register and memory cell, one row per instruction) catches the cases where a value has changed. The swap example from L09 is the classic version of this.

Every time, do this
  1. Write the register map.
  2. Write a Meaning for every line, as C.
  3. Collect the Meanings into C, and check the order of the stores.

M10C → assembly for pointer code

How it's asked
Write the x86-64 assembly for void inc2(long *p) { p[1] = p[0] + 2; }.
The answer, written exactly like this
inc2:                       # p in %rdi
  movq (%rdi), %rax         # rax = p[0]
  addq $2, %rax             # rax = p[0] + 2
  movq %rax, 8(%rdi)        # p[1] = rax   (element 1 is at +8 bytes)
  ret
How it works

Writing assembly is M9 in reverse. Every C pointer expression becomes an addressing mode:

CAssembly (long *p in %rdi)
*p or p[0](%rdi)
p[k] (constant k)8k(%rdi), e.g. p[2] → 16(%rdi) (4k for int)
*p = 7movq $7, (%rdi)
*q = *ptwo moves through a register (no memory-to-memory)

Use a caller-saved scratch register (%rax, %rcx, %rdx…) for temporaries. If the function returns a value, leave it in %rax, and always finish with ret. Arithmetic can also work directly on memory (addq $2,(%rdi)), which is often what the compiler does for *p += 2.

Every time, do this
  1. Write the register map, and convert each p[k] to a byte offset.
  2. Load, compute, then store: one line per C operation, each with a comment.
  3. Return the value in %rax (if any), then write ret.

(a) movq (%rsi),%rax    # rax = *b
    movq %rax,(%rdi)    # *a = *b
    movq $0,(%rsi)      # *b = 0
    C:  void f(long *a, long *b) { *a = *b; *b = 0; }

(b) put:                       # p in %rdi, v in %rsi
      movq %rsi, 16(%rdi)      # p[2] is at p + 2·8 = 16 bytes
      movq $7, (%rdi)          # *p = 7
      ret

1 movq (%rsi),%rax     rax = *yp          → y
2 movq (%rdx),%rcx     rcx = *zp          → z
3 movq %rax,(%rdx)     *zp = y
4 movq (%rdi),%rax     rax = *xp          → x   (rax reused; y no longer needed)
5 movq %rcx,(%rdi)     *xp = z
6 movq %rax,(%rsi)     *yp = x
C: void decode2(long *xp, long *yp, long *zp) {
     long x = *xp, y = *yp, z = *zp;
     *zp = y;  *xp = z;  *yp = x;
   }
