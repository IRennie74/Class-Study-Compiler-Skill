Solving method — stack, call/ret, frames, recursion

  1. Stack traces: keep a table with columns instruction | %rip | %rsp | top of stack | key registers. Use these rules:
    • push: rsp −= 8, then write.
    • pop: read, then rsp += 8.
    • call: push (call address + call length), then rip = target.
    • ret: rip = M[rsp], then rsp += 8.
  2. Argument location: count the integer/pointer arguments in order: %rdi, %rsi, %rdx, %rcx, %r8, %r9 (use the size-matched name, e.g. %esi for an int). Arguments 7+ are at 8(%rsp), 16(%rsp), … when the callee starts. Floating-point arguments use %xmm0, %xmm1, … with their own separate count.
  3. Locals on the stack: subq $N,%rsp allocates the space, and k(%rsp) is a local. A local goes on the stack when its address is taken (leaq k(%rsp)), or when it is an array or struct. Draw the frame from high addresses (return address) down to %rsp.
  4. Register-saving: a value needed after a call must live in a callee-saved register (rbx, rbp, r12–r15) or on the stack. Using a callee-saved register means push it in the prologue and pop it, in reverse order, in the epilogue.
  5. Recursion → C: answer four questions.
    1. Base case: which test jumps straight to ret, and what is %rax then?
    2. Saved value: what goes into %rbx (or another callee-saved register)?
    3. Recursive argument: how is %rdi changed before the call?
    4. Combine: what is done to %rax after the call?

How to show your work: model answer (3.35 rfun)

rfun:                      x in %rdi
  pushq %rbx               save the caller's rbx (callee-saved)
  movq  %rdi,%rbx          rbx = x            ← (b) the saved value is x
  movl  $0,%eax            rax = 0
  testq %rdi,%rdi
  je    .L2                if x == 0 → return 0      ← (a) base case
  shrq  $2,%rdi            rdi = x >> 2       ← (c) nx = x >> 2
  call  rfun               rax = rv = rfun(nx)
  addq  %rbx,%rax          rax = x + rv       ← (d) combine
.L2:
  popq  %rbx               restore
  ret

C:  long rfun(unsigned long x) {
      if (x == 0) return 0;
      unsigned long nx = x >> 2;
      long rv = rfun(nx);
      return x + rv;
    }
Check: rfun(20) = 20 + rfun(5) = 20 + 5 + rfun(1) = 20 + 5 + 1 + rfun(0) = 26

5.1 
pushq %rax   rsp = 0x7FF8, M[0x7FF8] = 0xA
pushq %rbx   rsp = 0x7FF0, M[0x7FF0] = 0xB
popq  %rax   rax = 0xB,  rsp = 0x7FF8

5.5 
twice:
  pushq %rbp              # we will use rbp and rbx → save the caller's values
  pushq %rbx
  subq  $8, %rsp          # keep 16-byte alignment at the calls (optional detail)
  movq  %rdi, %rbp        # x must survive BOTH calls → callee-saved %rbp
  call  f                 # rax = a
  movq  %rax, %rbx        # a must survive the 2nd call → callee-saved %rbx
  leaq  (%rax,%rbp), %rdi # arg = a + x
  call  f                 # rax = b
  imulq %rbx, %rax        # a*b
  addq  %rbp, %rax        # + x
  addq  $8, %rsp
  popq  %rbx              # reverse order of the pushes
  popq  %rbp
  ret
x is needed after both calls; a is needed after the second. b is used immediately, so it needs
no saving. Any two of rbx, rbp, r12–r15 are fine.
5.6 
(a) base: n ≤ 0 → return 0   (b) saved: rbx = n   (c) arg: n − 1   (d) combine: rax + 2·rbx
long rs(long n) { if (n <= 0) return 0; long rv = rs(n - 1); return rv + 2*n; }
rs(3) = 6 + rs(2) = 6 + 4 + rs(1) = 6 + 4 + 2 + 0 = 12   (in general n(n+1))
Stack: each recursing level pushes rbx (8) + a return address (8) = 16 bytes.
rs(3) → rs(2) → rs(1) → rs(0) is 3 levels × 16 = 48 bytes.

(a) False: %r12 is callee-saved, so the callee must push and pop it if it uses it.

5.9 
(a) base: x ≤ 1 (unsigned, jbe) → return 1   — note the push happens BEFORE the test, so .L2 pops
(b) saved: rbx = x   (c) arg: x >> 1   (d) combine: (x & 1) + 2·rv
unsigned long rf(unsigned long x) {
  if (x <= 1) return 1;
  unsigned long rv = rf(x >> 1);
  return 2*rv + (x & 1);
}
rf(13): 13 → 6 → 3 → 1 (base = 1).  Returns: rf(3) = 2·1 + 1 = 3; rf(6) = 2·3 + 0 = 6;
        rf(13) = 2·6 + 1 = 13.   (For x ≥ 1 it rebuilds x bit by bit, so it returns x.)
