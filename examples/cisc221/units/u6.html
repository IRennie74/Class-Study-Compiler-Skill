Methods for this unit: each practice problem lists the ones it uses

  1. Sizes and 1-D addresses. Write K (the element size) first: char 1, short 2, int 4, long/double/any pointer 8. Total = K·L. &A[i] = x + K·i.
  2. Expression tables. Decide the type first. An address (A+k, &A[i]) → value = x + K·k → leaq into %rax. An element (A[k], *(A+i)) → value = M[x + K·k] → mov with the element's suffix into %ax/%eax/%rax. Pointer arithmetic scales by K. A pointer difference (&A[i] − &A[j]) is an element count (long) = i − j.
  3. Scale limit. The scale can only be 1, 2, 4 or 8. For A[2*i] with 8-byte elements (16i), first compute 2i (leaq (%rsi,%rsi)), then use scale 8.
  4. Nested array addresses. For T A[R][C]: &A[i][j] = x + K(i·C + j), and row A[i] starts at x + i·C·K. sizeof = R·C·K. Only C (the 2nd dimension) is used in the address.
  5. Writing nested access without imul. Build i·C with leaq/shift/sub (7i = 8i − i, 5i = (i,i,4)), add j, then mov A(,%reg,K).
  6. Finding dimensions from assembly. Annotate until you see each array's index expression (e.g. 7i + j). The multiplier of the first index is that array's column count. Do each array separately, remembering which dimension is the 2nd one.
  7. Multi-level arrays. T *A[]: element = M[ M[x + 8i] + K·j ], which is two memory reads (first the row pointer, then the element). Rows are separate arrays and can have different lengths.
  8. Fixed vs. variable dimensions. A fixed N (#define) lets the compiler multiply by C·K with shifts and leaq. A variable n is unknown at compile time, so it needs imulq for n·i.
  9. Array loops. Use the Unit 4 loop methods, with the element accessed as (base,i,K): i in a register, an init of 0, addq $1 as the update, a cmp with n, and jl back (jump-to-middle at -Og).

How to show your work: model answer (L14 sum_element: find M and N)

long A[M][N];  long B[N][M];   return A[i][j] + B[j][i];     i → rdi, j → rsi, K = 8
leaq (,%rdi,8),%rdx      rdx = 8i
subq %rdi,%rdx           rdx = 7i
addq %rsi,%rdx           rdx = 7i + j        ← index into A = i·N + j  ⇒ N = 7
leaq (%rsi,%rsi,4),%rax  rax = 5j
addq %rax,%rdi           rdi = 5j + i        ← index into B = j·M + i  ⇒ M = 5
movq B(,%rdi,8),%rax     rax = M[B + 8(5j + i)]   = B[j][i]
addq A(,%rdx,8),%rax     rax += M[A + 8(7i + j)]  = A[i][j]
Answer: M = 5, N = 7

6.5 
rax = 5i → rax = j + 2·5i = 10i + j      → X's index = i·S + j  ⇒ S = 10
rdx = j → 4j → 4j + i                    → Y's index = j·R + i  ⇒ R = 4
movl X(,%rax,4) = X[i][j];  subl Y(,%rdx,4) = − Y[j][i]
Answer: R = 4, S = 10.
(X is [R][S], so X's row length is S; Y is [S][R], so its row length is R.)

(a) gt:  salq $2, %rsi                # 4j
         addq T(,%rdi,8), %rsi        # p = T[i] + 4j     (read #1: the pointer)

(c) Each T[i] is a separate pointer, so each row is its own array, anywhere in memory

zero:  movl  $0, %eax             # i = 0
       jmp   .L2                  # goto test
.L3:   movq  $0, (%rdi,%rax,8)    # a[i] = 0
       addq  $1, %rax             # i++
.L2:   cmpq  %rsi, %rax           # i : n

       ret

fm:  leaq (%rsi,%rsi,2), %rax     # 3i
     salq $5, %rax                # 96i   (3i · 32)

vm: n is not known at compile time, so it must use imulq (n·i), as in the lecture's var_ele:
     imulq %rdx,%rdi ; leaq (%rsi,%rdi,8),%rax ; movq (%rax,%rcx,8),%rax
     (n in %rdi, a in %rsi, i in %rdx, j in %rcx)
6.9 
INIT rax = 0 (sum), rdx = 0 (i) │ jmp test → jump-to-middle
BODY: rcx = a[i]; if (rcx > 0) sum += rcx   (jle .L3 skips the add when a[i] ≤ 0)
UPDATE i++ │ TEST i < n
long sumpos(long *a, long n) {
  long sum = 0;
  for (long i = 0; i < n; i++)
    if (a[i] > 0) sum += a[i];
  return sum;
}
  • I find K before anything else.
  • I use leaq for addresses and mov for elements.
  • For [R][C], I use C (not R) in the formula.
  • I read the dimensions from the index multipliers.
  • I remember that multi-level arrays need two reads.
