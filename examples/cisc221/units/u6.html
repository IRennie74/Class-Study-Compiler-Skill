M1Sizes and 1-D addresses

How it's asked
(Practice Problem 3.36 style) Fill in the element size, the total size and the address of element i for: int A[6]; char *B[4]; short C[10]; double D[3];
The answer, written exactly like this
Array          Element size K   Total = K·L    &element i
int A[6]       4                24             x_A + 4i
char *B[4]     8  (a pointer)   32             x_B + 8i
short C[10]    2                20             x_C + 2i
double D[3]    8                24             x_D + 8i
How it works

An array T A[L] is one contiguous block of L elements, each K = sizeof(T) bytes, so L·K bytes in total. Element i starts K·i bytes after the start: &A[i] = xA + K·i.

The only trap is K: char 1, short 2, int/float 4, long/double 8, and every pointer is 8 on x86-64, whatever it points to (char *, short ** …). The element type of char *B[4] is char *, a pointer, so K = 8.

In assembly an array is just its start address. Indexing becomes the addressing mode (base, index, K), e.g. movl (%rdi,%rsi,4),%eax for int z[digit] (the lecture's get_digit). C does no bounds checking: val[5] on a 5-element array simply reads whatever is next in memory.

Every time, do this
  1. Find the element type, and write K (pointers = 8).
  2. Total = K × L.
  3. &element i = x + K·i.

M2Expression tables

How it's asked
(Practice Problem 3.37 style) int E[] starts at xE in %rdx, and the long i is in %rcx. For each expression give its type, its value, and assembly leaving it in %rax (pointer) or %eax (int): E+1, E[2], &E[i], E[i+1], &E[i]-E.
The answer, written exactly like this
Expression   Type    Value             Assembly
E+1          int *   x_E + 4           leaq 4(%rdx),%rax
E[2]         int     M[x_E + 8]        movl 8(%rdx),%eax
&E[i]        int *   x_E + 4i          leaq (%rdx,%rcx,4),%rax
E[i+1]       int     M[x_E + 4i + 4]   movl 4(%rdx,%rcx,4),%eax
&E[i]-E      long    i                 movq %rcx,%rax
How it works

In C, an array's name used in an expression acts as a pointer to element 0. That gives two kinds of expression:

  • Addresses (type T *): E, E+k, &E[i]. Pointer arithmetic is scaled: E+1 means "one element later" = +K bytes, not +1 byte. The value is a number, so the assembly is leaq (compute, don't read memory).
  • Elements (type T): E[k], *(E+k). The value is the memory at that address, so the assembly is mov with the element's size (movl for int, movw for short, movq for long).

Pointer difference: subtracting two pointers into the same array gives the number of elements between them (type long), not bytes. &E[i] − E = i.

Every time, do this
  1. Decide: address (pointer type) or element (T)?
  2. Value: x + K·index, or M[x + K·index].
  3. Address → leaq into %rax. Element → mov with T's suffix into the right-sized register.

M3Scale limit

How it's asked
long L[] is at %rdi and i is in %rsi. Write the assembly for return L[3*i];.
The answer, written exactly like this
Address = x_L + 8·(3i) = x_L + 24i       24 is not a legal scale (only 1, 2, 4, 8)
leaq (%rsi,%rsi,2), %rax       # rax = 3i       (build the index first)
movq (%rdi,%rax,8), %rax       # M[x_L + 8·3i]
ret
How it works

The addressing mode can multiply the index by only 1, 2, 4 or 8. If an index expression needs a bigger factor (3i elements of 8 bytes = 24i), the compiler first computes the scaled index into a register, using leaq, shifts or adds (Unit 2 M7), and then uses a legal scale for the element size. This is a common trap: writing (%rdi,%rsi,24) or (%rdi,%rsi,16) is invalid.

Every time, do this
  1. Write the byte offset as K × (index expression).
  2. If the multiplier isn't 1/2/4/8, compute the index expression first.
  3. Then use scale K.

M4Nested array addresses

How it's asked
int M[4][5] starts at address x. Give sizeof(M), the address of M[2][3], the start of row M[3], and a general formula for &M[i][j].
The answer, written exactly like this
R = 4 rows, C = 5 columns, K = 4
sizeof(M)  = R·C·K = 4·5·4 = 80
&M[2][3]   = x + K(i·C + j) = x + 4(2·5 + 3) = x + 52
row M[3]   = x + i·C·K = x + 3·5·4 = x + 60
&M[i][j]   = x + 4(5i + j) = x + 20i + 4j
How it works

Memory is one long line of bytes, so a 2-D array must be flattened. C uses row-major order: all of row 0, then all of row 1, and so on. Element [i][j] is therefore i·C + j elements from the start (skip i full rows of C elements, then j more):

  [0][0] [0][1] … [0][C−1] │ [1][0] [1][1] … │ … │ [i][0] … [i][j]
  <──────── row 0 ────────>│<── row 1 ──>    │   <─ i·C elements ─> + j

Multiply by K for bytes: &A[i][j] = x + K(i·C + j). Only C (the second dimension) appears. The number of rows R is needed only for sizeof. A[i] on its own is a whole row: an array of C elements, starting at x + i·C·K. The lecture's example is zip_dig pgh[4] = int pgh[4][5], with rows 20 bytes apart.

Every time, do this
  1. Write R, C and K.
  2. &A[i][j] = x + K(iC + j); row = x + iCK; size = RCK.
  3. Substitute the numbers, showing each step.

M5Writing nested access without imul

How it's asked
Write the assembly for int T[6][9]; int get(long i, long j) { return T[i][j]; }, with i in %rdi and j in %rsi, without imul.
The answer, written exactly like this
&T[i][j] = T + 4(9i + j)
get:  leaq (%rdi,%rdi,8), %rax     # 9i
      addq %rsi, %rax              # 9i + j
      movl T(,%rax,4), %eax        # M[T + 4(9i + j)]
      ret
How it works

Combine M4's formula with Unit 2's multiply-by-constant tricks. Build the element index i·C + j in a register (leaq/shift/sub for i·C, then add j), then let the addressing mode do the final ×K with the array's address as the displacement: T(,%rax,4) = T + 4·rax. This is the lecture's get_pgh_digit pattern (leaq (%rdi,%rdi,4) for 5i, add dig, movl pgh(,%rsi,4)).

Every time, do this
  1. Write &A[i][j] = A + K(iC + j).
  2. Build i·C with leaq/shift/sub, then add j.
  3. mov A(,%reg,K) with the element's suffix.

M6Finding dimensions from assembly

How it's asked
(Lecture sum_element style) Find M and N. Here i is in %rdi and j in %rsi. 
long A[M][N];
long B[N][M];
long sum_element(long i,
                 long j) {
  return A[i][j] + B[j][i];
}
leaq (,%rdi,8), %rdx
subq %rdi, %rdx
addq %rsi, %rdx
leaq (%rsi,%rsi,4), %rax
addq %rax, %rdi
movq B(,%rdi,8), %rax
addq A(,%rdx,8), %rax
ret
The answer, written exactly like this
rdx = 8i → 7i → 7i + j        used with A: index = i·N + j   ⇒ N = 7
rax = 5j ; rdi = 5j + i       used with B: index = j·M + i   ⇒ M = 5
Answer: M = 5, N = 7
How it works

The compiler bakes the column count into the index calculation (M4: index = row·C + col). So annotate until each array's index expression appears, then read off the multiplier of the row index. That multiplier is that array's column count, its second dimension. Be careful which constant is which: A is [M][N], so its column count is N; B is [N][M], so its column count is M. Check the scale too (8 → long elements).

Every time, do this
  1. Annotate until you see "c·i + j" for each array.
  2. Match it to that array's declaration: c = its 2nd dimension.
  3. Write each constant with the line that proves it.

M7Multi-level arrays

How it's asked
int *univ[3]; (each element points to an int array). (a) Write the assembly for int get(size_t i, size_t j) { return univ[i][j]; }. (b) How many memory reads does it take, compared with int pgh[4][5]?
The answer, written exactly like this
(a) get:  salq $2, %rsi               # 4j
          addq univ(,%rdi,8), %rsi    # p = univ[i] + 4j     ← read 1: the row pointer
          movl (%rsi), %eax           # *p                   ← read 2: the element
          ret
(b) univ[i][j] = M[ M[univ + 8i] + 4j ] → 2 memory reads.
    pgh[i][j] = M[ pgh + 20i + 4j ]    → 1 memory read.
How it works

A multi-level array is an array of pointers, each pointing to a separate row array. univ[i][j] looks the same in C as a nested array access, but the machine work is different:

  1. Read the pointer univ[i] (8 bytes at univ + 8i).
  2. Add 4j to it and read the int there.

So it takes two memory accesses, compared with one for a nested array, where the row position is computed arithmetically. Because the rows are separate arrays, they can be anywhere in memory and can have different lengths. A nested array is one block with a fixed row length.

Every time, do this
  1. Recognise an array of pointers (T *A[]).
  2. Formula: M[ M[A + 8i] + K·j ].
  3. Assembly: read the pointer, add K·j, read the element.

M8Fixed vs. variable dimensions

How it's asked
Explain why fix_ele (N = 16, a constant) uses a shift, but var_ele (n a parameter) uses imulq, to compute the address of a[i][j] for int elements.
The answer, written exactly like this
fix_ele: row size = C·K = 16·4 = 64 is known at compile time → salq $6 (×64)
var_ele: row size = n·4 depends on the parameter n → unknown at compile time
         → must multiply at run time: imulq %rdx,%rdi (n·i), then leaq/movl with scale 4
How it works

The address formula needs the row length C. If C is a compile-time constant (#define N 16), the compiler turns ×C·K into shifts and leaq tricks. If the array's dimension is a run-time value (C99 variable-length arrays int a[n][n], or manual indexing a[i*n + j] with #define IDX(n,i,j)), the compiler must emit a real imulq. That is the difference between the lecture's fix_ele and var_ele.

Every time, do this
  1. Is the row length a constant? → shifts/leaq. A variable? → imulq.
  2. Write the address formula both ways.

M9Array loops

How it's asked
Write -Og assembly for long total(int *a, long n) { long s = 0; for (long i = 0; i < n; i++) s += a[i]; return s; }
The answer, written exactly like this
total:                         # a in %rdi, n in %rsi
  movl   $0, %eax              # s = 0
  movl   $0, %edx              # i = 0
  jmp    .L2                   # jump-to-middle
.L3:
  movslq (%rdi,%rdx,4), %rcx   # (long) a[i]   (int → long: sign-extend)
  addq   %rcx, %rax            # s += a[i]
  addq   $1, %rdx              # i++
.L2:
  cmpq   %rsi, %rdx            # i : n
  jl     .L3                   # while i < n
  ret
How it works

An array loop is just a Unit 4 loop whose body uses the indexed addressing mode. Keep i in a register and access the element as (base,i,K). Use a jump-to-middle shape for -Og (or a guard + do-while for -O1), with the update addq $1 and a cmp with n.

Watch the element size and sign: adding an int element to a long sum needs movslq to sign-extend (Unit 1 M8). The lecture's zincr is the model: addl $1,(%rdi,%rax,4) with cmpq $4,%rax ; jbe (unsigned, because i is size_t).

Every time, do this
  1. Write the loop's goto form (Unit 4 M5).
  2. Element = (base, i, K), with the right mov size and sign.
  3. Comment every line.
