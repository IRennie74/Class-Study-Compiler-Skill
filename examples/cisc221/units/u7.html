Methods for this unit: each practice problem lists the ones it uses

  1. Struct layout table. Columns: field | size | alignment | offset | padding before. Each offset = the next multiple of the field's alignment (array → element size). K = the largest alignment. sizeof = the end, rounded up to a multiple of K.
  2. Minimise struct size. Reorder the fields by alignment, largest first, then recompute with the layout table.
  3. Arrays of structs. &a[i].f = a + i·sizeof(struct) + offset(f). sizeof already includes the end padding, so every element is aligned.
  4. Writing struct access in assembly. A field is offset(%reg). Following a pointer field means movq off(%rdi),%rax then access through (%rax). Match the instruction to the field's size and sign (int → long uses movslq; short → movzwl/movswl). For array elements use disp(,%idx,scale) after computing i·sizeof.
  5. Assembly → struct. Each k(%rdi) is a field at offset k, and the instruction size gives the field size (movq 8, movl 4, movw/movzwl 2, movb 1). A loaded value that is then used as an address is a pointer field. Rebuild the struct(s) and the C statement.
  6. Unions. All fields at offset 0; size = the largest member, rounded up to the union's alignment. Writing one field and reading another reinterprets the bits.
  7. Byte order. x86 is little endian: the least significant byte is at the lowest address. List the bytes from the right end of the hex number. Big endian is the reverse.
  8. Floating-point code. FP args in %xmm0, %xmm1…, result in %xmm0, all caller-saved. Scalar ops: movss/addss… for float, movsd/addsd… for double. Integer and pointer args still use %rdi… . The return value must end up in %xmm0.

How to show your work: model answer

struct S1 { char c; int i[2]; double v; };
Field   Size  Align  Offset  Padding before
c       1     1      0       —
i[2]    8     4      4       3 bytes (1..3)
v       8     8      16      4 bytes (12..15)
end = 24 ; K = max(1,4,8) = 8 ; 24 is already a multiple of 8 → sizeof = 24

Assembly → field: "movslq 16(%rdi),%rax" → a 4-byte signed field at offset 16 (an int)
                  "movq 24(%rdi),%rdi"   → an 8-byte field at offset 24 that is then
                                           dereferenced → a pointer (r = r->next)

(a) tag 0, count 4, price 8, next 16, sizeof 24
(b) f:  movq   16(%rdi), %rax     # p->next

(c) count is an int (4 bytes, signed) multiplied with a long. It must be sign-extended

movl 8(%rdi) and addl 12(%rdi) → two ints at offsets 8 and 12: a, b
movq (%rdi),%rdx → an 8-byte pointer at offset 0: ptr
movl %eax,4(%rdx) → an int at offset 4 of the pointed-to struct
struct t { int u; int v; };

7.7 
Little endian: 0x600: 08  0x601: 07  0x602: 06  0x603: 05
               0x604: 04  0x605: 03  0x606: 02  0x607: 01
char at 0x603 = 0x05.   Big endian: 0x600 holds 01, …, so 0x603 would hold 0x04.
7.8 
(a) x %xmm0, n %rdi, y %xmm1, p %rsi; result in %xmm0
(b) add3:  addsd %xmm1, %xmm0      # a + b
           addsd %xmm2, %xmm0      # + c
           ret
(c) pf:    movss (%rdi), %xmm1     # t = *p
           addss %xmm0, %xmm1      # t += v
           movss %xmm1, (%rdi)     # *p = t
           ret                     # v is still in %xmm0 → the return value
7.9 
Layout: a@0, b@8, c@16, end 18 → K = 8 → sizeof = 24
&arr[i].c = arr + 24i + 16

       movzwl arr+16(,%rax,8), %eax   # M[arr + 16 + 8·3i]  (movw/movswl also accepted)
       ret
