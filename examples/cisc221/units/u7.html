Solving method — struct layout and access

  1. Make a layout table: field | size | alignment (= size for primitives; for an array, the element size; for a nested struct, its K) | offset | padding before it.
  2. Walk the fields in order. Each offset = the next multiple of that field's alignment at or after the current end.
  3. K = the largest alignment of any field. sizeof = the end, rounded up to a multiple of K (end padding).
  4. Minimise: sort the fields by alignment, largest first, then recompute.
  5. Assembly → struct: each k(%rdi) is a field at offset k. The instruction size gives the field's size (movq = 8, movl/movslq = 4, movzwl/movw = 2, movzbl/movb = 1). A movq k(%rdi),%rdi followed by more (%rdi) accesses means you are following a pointer.
  6. Unions: size = the largest member, rounded up to the union's alignment. All offsets are 0.
  7. FP: count the FP args in %xmm0.. separately from the integer args in %rdi... The result is in %xmm0. s = single (float), d = double, p = packed.

How to show your work: model answer

struct S1 { char c; int i[2]; double v; };
Field   Size  Align  Offset  Padding before
c       1     1      0       —
i[2]    8     4      4       3 bytes (1..3)
v       8     8      16      4 bytes (12..15)
end = 24 ; K = max(1,4,8) = 8 ; 24 is already a multiple of 8 → sizeof = 24

Assembly → field: "movslq 16(%rdi),%rax" → a 4-byte signed field at offset 16 (an int)
                  "movq 24(%rdi),%rdi"   → an 8-byte field at offset 24 that is then
                                           dereferenced → a pointer (r = r->next)

movq (%rdi),%rdx → an 8-byte pointer at offset 0: ptr
movl %eax,4(%rdx) → an int at offset 4 of the pointed-to struct

7.8 
(a) x %xmm0, n %rdi, y %xmm1, p %rsi; result in %xmm0
(b) add3:  addsd %xmm1, %xmm0      # a + b
           addsd %xmm2, %xmm0      # + c
           ret
(c) pf:    movss (%rdi), %xmm1     # t = *p
