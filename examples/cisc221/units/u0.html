M1Bits, bytes and hex

How it's asked
(a) Write 0x2C in binary and in decimal. (b) How many bytes long is the value 0x1122334455667788?
What you're looking at

0x at the front means "this number is written in hexadecimal (base 16)". 2C is the number itself. Binary means base 2 (only 0s and 1s). Decimal is the normal base 10 we count in. A byte is a unit of computer memory, explained below.

The answer, written exactly like this
(a) hex digit:   2      C
    binary:      0010   1100        → 0x2C = 0010 1100₂
    decimal:     2·16 + 12 = 44     → 0x2C = 44
(b) 16 hex digits ÷ 2 digits per byte = 8 bytes
How it works

Computers store everything as bits. A bit is a single 0 or 1, like a switch that is off or on. One bit can't hold much, so bits are grouped:

  • 8 bits = 1 byte. The byte is the basic unit of memory. One byte can hold 2⁸ = 256 different values (0 to 255).
  • Bigger values use several bytes: 2, 4 or 8. An 8-byte value has 64 bits, which is why x86-64 is called a "64-bit" machine.

Why hex? Long strings of bits are unreadable (0010110010101111…), so we write them in base 16. The trick that makes hex useful: one hex digit is exactly 4 bits, so two hex digits are exactly one byte. The 16 hex digits are 0–9, then A=10, B=11, C=12, D=13, E=14, F=15.

hex0123456789ABCDEF
binary0000000100100011010001010110011110001001101010111100110111101111

Converting: hex → binary means replacing each hex digit with its 4 bits. Hex → decimal works like decimal place values, but in powers of 16: the rightmost digit counts 1s, the next counts 16s, the next 256s. So 0x2C = 2·16 + 12 = 44, and 0x100 = 1·256 = 256.

Counting bytes: count the hex digits after 0x and divide by 2.

Every time, do this
  1. Hex → binary: replace each digit with its 4 bits (use the table).
  2. Hex → decimal: digit × 16position, then add up.
  3. Bytes = number of hex digits ÷ 2.

M2Hex arithmetic

How it's asked
(Inside bigger problems you'll constantly need:) (a) 0x100 + 0x8 (b) 0x108 + 0x10 (c) 0xAB − 3 (d) 0x11 × 16 (e) 0xF8 + 0x8
What you're looking at

All of these are numbers written in hex (because they start with 0x, except the plain 3 and 16, which are ordinary decimal numbers). You do the maths in hex and write the answer in hex.

The answer, written exactly like this
(a) 0x100 + 0x8  = 0x108           (8 just goes in the last digit)
(b) 0x108 + 0x10 = 0x118           (add 1 to the 16s digit)
(c) 0xAB − 3     = 0xA8            (B=11, 11 − 3 = 8)
(d) 0x11 × 16    = 0x110           (×16 = shift one hex digit left, add a 0)
(e) 0xF8 + 0x8   = 0x100           (8+8 = 16 = 0x10: write 0, carry 1;
                                    F+1 = 16: write 0, carry 1)
How it works

Hex arithmetic works exactly like decimal arithmetic, except that you carry at 16 instead of 10. In decimal, 9 + 1 = 10 (write 0, carry 1). In hex, F + 1 = 0x10 (F is 15, and 15 + 1 = 16 = "1 sixteen and 0 ones").

The shortcuts that matter in this course:

  • Adding a small number to an address usually changes only the last digit or two: 0x100 + 8 = 0x108.
  • Multiplying by 16 moves every hex digit one place left (like ×10 in decimal): 0x13 × 16 = 0x130.
  • Multiplying by 2, 4 or 8: convert to decimal if it's easier, then back. 4 × 3 = 12 = 0xC.
  • Memory addresses in problems are usually 8 apart (0x100, 0x108, 0x110, 0x118), because 8 bytes is the size of a long. 0x108 + 8 = 0x110, because 8 + 8 = 16 = 0x10 (carry).
Every time, do this
  1. Line the numbers up by their last digit.
  2. Add digit by digit; whenever a column reaches 16 or more, subtract 16 and carry 1.
  3. Double-check the carries.

M3Negative numbers (two's complement)

How it's asked
(a) The byte 0xFF: what number is it as an unsigned char, and as a signed char? (b) Write −1 as an 8-byte hex value. (c) Is the byte 0x80 negative when read as signed?
What you're looking at

unsigned char and signed char are C types for 1-byte numbers. "Unsigned" means it can only be zero or positive. "Signed" means it can be negative too. The question asks what the same 8 bits mean under each interpretation.

The answer, written exactly like this
(a) 0xFF = 1111 1111₂
    unsigned: 255
    signed:   top bit is 1 → negative → 255 − 256 = −1
(b) −1 = all bits 1 = 0xFFFFFFFFFFFFFFFF
(c) 0x80 = 1000 0000₂ → top bit 1 → negative: 128 − 256 = −128 (yes)
How it works

Bits are just 0s and 1s. The same bits can mean different numbers, depending on whether you treat them as unsigned (never negative) or signed (can be negative). The computer doesn't store which one you meant: the instructions decide. That's why later units have separate "signed" and "unsigned" versions of shifts, comparisons and extensions.

Two's complement is how signed numbers are stored. The rule: the top bit (the leftmost one) is the sign bit. If it's 0, the number is the same as unsigned. If it's 1, the number is negative, and its value is (the unsigned value) − 2bits. For one byte: values with top bit 1 (0x80–0xFF) mean 128 − 256 = −128 up to 255 − 256 = −1.

 unsigned:   0 ... 127 | 128 ... 255
 signed:     0 ... 127 | −128 ... −1        (same bits, different meaning)
 hex:      0x00 .. 0x7F | 0x80 .. 0xFF

Useful facts: −1 is always all 1s (0xFF, 0xFFFF, 0xFFFFFFFF…). A hex number whose first digit is 8–F has its top bit set, so it is negative if signed. To negate a number: flip all its bits and add 1 (that's what negq does later).

Every time, do this
  1. Look at the first hex digit: 0–7 means positive; 8–F means negative if signed.
  2. Negative value = unsigned value − 2bits (256 for 1 byte).
  3. Remember: −1 = all F's.

M4The machine: CPU, registers, memory, addresses

How it's asked
Memory: 0x100: 0xFF, 0x108: 0xAB, 0x110: 0x13. Register: %rax = 0x108. (a) What is M[0x110]? (b) What is in %rax? (c) What is M[%rax]?
What you're looking at

The memory list is a table of address: value pairs. 0x100, 0x108 and 0x110 are addresses (locations), and 0xFF, 0xAB and 0x13 are the values stored there. M[a] is shorthand for "the value stored in memory at address a". %rax is the name of a register (a storage box inside the CPU). M[%rax] means: take the number in %rax, use it as an address, and look up what is stored there.

The answer, written exactly like this
(a) M[0x110] = 0x13                    (look up address 0x110)
(b) %rax = 0x108                       (the register's own contents)
(c) M[%rax] = M[0x108] = 0xAB           (use 0x108 as an address, look it up)
How it works

A computer, as this course sees it, has two parts:

   CPU (the worker)                          MEMORY (the storage)
 ┌──────────────────────┐   addresses   ┌──────────────────────────┐
 │ registers: 16 boxes  │ ────────────▶ │ address   value          │
 │  %rax %rbx … %r15    │ ◀── data ───▶ │ 0x100     0xFF           │
 │ %rip: next instruction│              │ 0x108     0xAB           │
 │ condition codes      │ ◀─ program ── │ 0x110     0x13   …       │
 └──────────────────────┘               └──────────────────────────┘
  • Memory is a huge row of numbered byte-sized boxes. A box's number is its address. Programs, data and the stack all live in memory. It's big but slow.
  • Registers are 16 tiny boxes inside the CPU, each holding 8 bytes. They're very fast but very few, so the CPU loads values from memory into registers, works on them there, and stores results back. (The lecture's analogy: registers are the chef's cutting board, memory is the fridge.)
  • %rip, the program counter, holds the address of the next instruction to run. The condition codes are a few 1-bit flags describing the last calculation (Unit 3).

The key idea: an address is just a number. The same number can be data (%rax = 0x108) or be used as a location (M[0x108]). Telling those two apart is half of every question in this course.

Every time, do this
  1. A register name means its own contents.
  2. M[something] or (something): compute the address, then look it up in the memory table.

M5Reading one line of assembly

How it's asked
For the instruction addq %rsi, 8(%rdi): name the operation, the data size, the source and the destination, and say in words what it does.
What you're looking at

This is one assembly instruction, one command for the CPU. addq is the command name. %rsi and 8(%rdi) are its two operands: the things it works on, separated by a comma.

The answer, written exactly like this
addq      %rsi        ,   8(%rdi)
│  │      │               │
│  └ q = 8 bytes (quad)    └ destination: memory at address %rdi + 8
└ add     └ source: register %rsi
In words: M[%rdi + 8] = M[%rdi + 8] + %rsi
          (add the value in %rsi to the 8 bytes in memory at %rdi + 8)
How it works

A C program is translated into a long list of tiny instructions, each doing one small step. This course uses AT&T syntax, where every instruction looks like:

  operation+size   source, destination      e.g.  movq  %rax, %rbx
  • Operation: mov (copy), add, sub (subtract), imul (multiply), lea, cmp (compare), jmp (jump) …
  • Size letter on the end: b = 1 byte, w = 2, l = 4, q = 8. movq = "move a quad (8 bytes)".
  • Source first, destination last. The result goes into the last operand. subq %rax,%rbx means rbx = rbx − rax.

The operand symbols, which you'll see on every page:

Looks likeMeansExample
%namea register%rax
$numbera constant number$5 = the number 5
(%reg)memory at the address held in reg(%rdi) = M[%rdi]
8(%reg)memory at reg + 88(%rdi) = M[%rdi + 8]
.L2: / name:a label: a name for a spot in the codejumps go to labels
# texta comment (ignored by the CPU)# x = y
Every time, do this
  1. Split the line into operation, size letter, source and destination.
  2. Translate each operand with the symbol table.
  3. Say it in words: destination = destination (op) source.

M6C pointers and types

How it's asked
long x = 5; long *p = &x; *p = 7; (a) What is x now? (b) What does p hold? (c) How many bytes is a long, an int, a char, and a pointer?
What you're looking at

This is C code. long is a type (a whole number stored in 8 bytes). long *p declares p as a pointer to a long. &x means "the address of x". *p means "the thing p points to".

The answer, written exactly like this
(a) p points to x, so *p = 7 changes x → x = 7
(b) p holds the ADDRESS of x (where x lives in memory, e.g. 0x7ffd…)
(c) char 1 · short 2 · int 4 · long 8 · any pointer 8   (bytes, on x86-64)
How it works

Every variable lives somewhere in memory, at some address. A pointer is a variable whose value is an address, the location of something else.

  memory:   address 0x500: x = 5          p = 0x500  (p "points to" x)
  *p = 7  → go to the address in p (0x500) and store 7 there → x is now 7
  • &x means "address of x" (gives a pointer).
  • *p means "go to the address in p" (to read or write what's there). This is called dereferencing.
  • p[i] means "element i after p" = *(p + i). Arrays and pointers work the same way.
  • p->field means "a field of the struct that p points to" (Unit 7).

Why this matters for assembly: a pointer is an address in a register, and *p is the parentheses in assembly. If p is in %rdi, then *p is (%rdi). Types matter because they decide how many bytes are read or written: an int is 4 bytes (suffix l) and a long is 8 (suffix q). On x86-64 every pointer is 8 bytes.

Every time, do this
  1. & = "address of", * = "go to the address".
  2. Write down the size of each type (char 1, short 2, int 4, long and pointers 8).

M7What a function looks like in assembly

How it's asked
long f(long x, long y)
x in %rdi, y in %rsi
f:
  leaq  (%rdi,%rsi), %rax
  addq  $1, %rax
  ret
(a) Which registers hold the inputs, and which holds the result? (b) What does f(3, 4) return? (c) Write the C.
What you're looking at

The first line is the function's C prototype: its name, inputs (x, y) and output type. The comment line tells you which registers the inputs arrive in. f: is a label marking where the function's code starts. Each indented line is one instruction. ret means "return to whoever called me".

The answer, written exactly like this
(a) inputs: x in %rdi, y in %rsi      result: %rax (always the return value)
(b) rax = 3 + 4 = 7 ; rax = 7 + 1 = 8  → f(3,4) = 8
(c) long f(long x, long y) { return x + y + 1; }
How it works

A function in assembly is just a label followed by instructions and ending with ret. There are no named variables: by agreement (the calling convention), inputs arrive in fixed registers, and the answer is left in a fixed register:

  • 1st input in %rdi, 2nd in %rsi, 3rd in %rdx, then %rcx, %r8, %r9.
  • The result is returned in %rax.

So reading a function means following the values through the registers, line by line, until %rax holds the answer at ret. Problems usually give you the C prototype and the line "x in %rdi, y in %rsi" for this reason. Many questions show a C version with blanks (______) and ask you to fill them in so the C does the same thing as the assembly.

Every time, do this
  1. Write which variable is in which register (inputs) and that the result goes in %rax.
  2. Go line by line, writing what each register holds.
  3. At ret, %rax is the answer.

M8How to read a typical problem page

How it's asked
(This is what most test questions in this course look like:) 
long scale2(long x, long y, long z) {
    long t = __________;
    return t;
}
long scale2(long x, long y, long z)
x in %rdi, y in %rsi, z in %rdx
scale2:
  leaq (%rdi,%rdi,4), %rax
  leaq (%rax,%rsi,2), %rax
  leaq (%rax,%rdx,8), %rax
  ret
Fill in the missing expression in the C code.
What you're looking at

On the left is C code with a blank (______): part of the program is hidden. On the right is the assembly the compiler produced from the complete C code. Your job is to work out what the blank must be, by reading what the assembly computes. The gray line "x in %rdi …" tells you where each input is.

The answer, written exactly like this
Map: x → %rdi, y → %rsi, z → %rdx
leaq (%rdi,%rdi,4),%rax    rax = x + 4x = 5x
leaq (%rax,%rsi,2),%rax    rax = 5x + 2y
leaq (%rax,%rdx,8),%rax    rax = 5x + 2y + 8z
Answer: long t = 5*x + 2*y + 8*z;
How it works

Nearly every question in this unit of the course is reverse engineering: you're shown what the machine does, and you work out what the C program must have said. The question page always has the same parts:

  • The C template: the program with blanks (expressions, conditions, case numbers…).
  • The assembly: the compiled code, with a label at the top and usually ret at the end.
  • The register line ("x in %rdi …"): your starting point.
  • Sometimes tables (memory and register values) and lettered parts (A, B, C) asking for explanations.

The method that always works: write which variable is in which register, then go line by line, writing in plain algebra what the destination register now holds. When you reach the end, the expressions you've written are the C. Every later unit teaches what a new kind of instruction means, so you can keep doing exactly this. (leaq, used here, is explained in Unit 2: (a,b,S) computes a + S·b.)

Every time, do this
  1. Find the three parts: the C template, the register line, the assembly.
  2. Write the register map.
  3. Annotate every assembly line in algebra, then fill the blanks.
