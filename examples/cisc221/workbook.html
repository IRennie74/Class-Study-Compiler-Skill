Unit 1 — Foundations: registers, operands, addressing, mov

L09–L10 · 11 practice problems · full worked solutions follow the practice set
Key facts you need for these problems
  • 16 registers: %rax %rbx %rcx %rdx %rsi %rdi %rsp %rbp %r8–%r15; sub-names %eax/%ax/%al, %r8d/%r8w/%r8b.
  • Operand kinds: $imm (a constant), %reg (its contents), memory D(Rb,Ri,S) = M[D + Rb + S·Ri]. S ∈ {1,2,4,8}; Ri ≠ %rsp. A bare number is an absolute address.
  • Suffixes b/w/l/q = 1/2/4/8 bytes. No memory→memory moves; an immediate is never a destination.
  • A 32-bit register write zeroes the upper 32 bits; 8/16-bit writes don't.
  • movz/movs widen according to the SOURCE type; narrowing = load at full size, store the low part.
  • Toolchain: .c → (gcc -S) .s → (as) .o → (ld + .a) executable; objdump -d disassembles. ISA vs microarchitecture.

Solving method — operand and memory questions

  1. Classify the operand before you compute anything. If it starts with $, it is an immediate: the answer is that number and you read no memory. A bare register (%rax) means its contents. Anything else (parentheses, or a bare number like 0x104) is a memory operand.
  2. For memory, compute the address with Addr = D + Rb + S·Ri. Convert everything to one base first. Displacements written without 0x are decimal.
  3. Look the address up in the memory table. The value stored there is the answer.
  4. For suffix questions, read the size from the register that is not inside parentheses (8-bit names like %al, %bl, %sil → b; 16-bit like %ax, %si → w; %eXX or %rNd → l; %rXX → q).
  5. For "what's wrong" questions, check this list in order: memory-to-memory; immediate as destination; suffix doesn't match the register; the register doesn't exist; a 32-bit register used as an address; %rsp used as the index; scale not in {1,2,4,8}.
  6. For cast moves (*dp = (dest_t)*sp): if the destination is wider, sign- or zero-extend according to the source type. If it is narrower, load at the source size and store the low part. If the sizes are equal, use a plain mov.

Unit 2 — Arithmetic, leaq and reverse-engineering

L10 · 10 practice problems · full worked solutions follow the practice set
Key facts you need for these problems
  • op S,D means D = D op S. subq S,D is D − S. sal/shl = <<, sar = signed >>, shr = unsigned >>.
  • inc/dec/neg (−x)/not (~x) take one operand. A shift with one operand shifts by 1.
  • leaq D(a,b,S),d → d = D + a + S·b. No memory access, no flags. Used for &x[i] and for x + k·y.
  • Multiply tricks: (r,r,2) = 3r, (r,r,4) = 5r, (r,r,8) = 9r, then salq $k multiplies by 2^k.
  • add/sub/imul are the same for signed and unsigned. xor r,r = 0. cqto + idivq does signed division (quotient in rax, remainder in rdx).

Solving method — "fill in the C" for straight-line arithmetic

  1. Register map. From the prototype, write x → %rdi, y → %rsi, z → %rdx (then %rcx, %r8, %r9).
  2. Annotate every line. Next to each instruction, write the new value of the destination (the second operand) as an expression in the original variables. Use these translations:
    InstructionWrite
    leaq D(a,b,S), dd = D + a + S·b
    subq s, dd = d − s (reversed from how it reads)
    salq k, dd = d · 2k
    sarq k, d / shrq k, dd = d >> k (signed / unsigned)
    notq d / negq dd = ~d / d = −d
    xorq r, rr = 0
  3. Track register reuse. When a register is overwritten, its old meaning is gone. Cross it out in your map.
  4. Match to the blanks. The C temporaries (t1, t2, …) are usually the values after particular lines. The compiler may merge two C lines into one leaq, or reorder independent ones.
  5. Verify with numbers. Pick x = 1, y = 2, z = 3, run both the assembly (on your annotations) and your C, and check that they agree. It takes 30 seconds and catches most sign and order mistakes.

Unit 3 — Condition codes, branches, conditional moves

L11 · 11 practice problems · full worked solutions follow the practice set
Key facts you need for these problems
  • Flags: CF unsigned overflow, ZF zero, SF negative, OF signed overflow. leaq sets none.
  • cmp b,a → a − b; test b,a → a & b. Read 'cmp b,a ; jX' as 'if (a X b)'.
  • Signed: g ge l le (SF^OF). Unsigned: a ae b be (CF). Either: e ne s ns.
  • setX writes 1 byte → movzbl. The compiler jumps on the NEGATED C test to skip the then-block.
  • cmov: both values are computed, then one is chosen. Not used when a side might fault, be expensive, or have side effects.

Solving method — flags, comparisons, and if/else → C

  1. Flags: for cmp b,a, compute a − b twice: once as signed numbers (gives SF, ZF, OF) and once as unsigned (gives CF). CF = 1 when the unsigned a < b (a borrow). OF = 1 when signed a − b falls outside the type's range.
  2. Jumps and sets: read cmp b,a ; jX L as "if (a X b) goto L". Letters: g/l = signed; a/b = unsigned; e/ne = either.
  3. Types from compares: the suffix gives the size (b char, w short, l int, q long/pointer). The jump or set letter gives signedness.
  4. if/else → C:
    1. Annotate the arithmetic, as in Unit 2.
    2. Label each block: everything up to the first jump, then each label.
    3. For each conditional jump, write the condition on both edges (the jump edge = the jump's condition; the fall-through edge = its negation).
    4. The fall-through condition is the C if test (the compiler jumps over the then-block when the test is false).
    5. A value computed before any test is the initial value (val = …). Each ret ends one path.
    6. Fill the template, then test it with two inputs, one going down each path.
  5. cmov: the value already in %rax is the "default". cmovX s,%rax means "if X, use s instead". Both values are always computed.

Unit 4 — Loops and switch statements

L11–L12 · 11 practice problems · full worked solutions follow the practice set
Key facts you need for these problems
  • do-while: test at the bottom. while (-Og): jump-to-middle (jmp test first). while (-O1): guarded-do (a test before the loop + a do-while).
  • for (I;T;U) B ≡ I; while (T) { B; U; }. The guard can disappear if the compiler proves the first test is true.
  • Switch: jump table of 8-byte addresses, jmp *.L(,%reg,8). One unsigned ja catches both below and above the range.
  • Offset subtraction → smallest case; cmp constant + offset → largest case. Entries equal to default = missing; repeated labels = shared; no jmp at the end of a block = fall-through.

Solving method — loops

  1. Find the loop: circle every jump to an earlier label (the back-edge). The code between that label and the back-edge is the loop.
  2. Classify the translation:
    You seeIt is
    no jump before the loop label; the test is only at the bottomdo-while
    jmp .Ltest right before the body (the test is at the bottom)while, jump-to-middle (-Og)
    a test before the loop that jumps past it, then the same test at the bottomwhile, guarded-do (-O1)
  3. Label the parts: Init = the movs before the loop. Test = the cmp/test + back-edge jump (the C condition is the jump's condition, because the back-edge is taken when the loop continues). Update = the add/sub of the counter just before the test. Body = the rest.
  4. Write it as a while. Convert to a for if there is a clear Init/Test/Update on one variable.
  5. Trace a small input in an iteration table to check your answer and to answer "what does it compute?".

Solving method — switch

  1. Offset k from subq $k / addq $−k / leaq −k(%rdi). Without one, k = 0. Table index i ↔ case i + k.
  2. Max case = (the constant in cmpq $n) + k. ja → the default label.
  3. Write a mapping table: index → case value → label.
  4. Entries that equal the default label are missing cases. Labels that appear twice are shared cases.
  5. Translate each label's block. A block with no jmp/ret at its end falls through into the next label.

Unit 5 — Procedures: stack, calls, conventions, recursion

L12–L13 · 9 practice problems · full worked solutions follow the practice set
Key facts you need for these problems
  • The stack grows down; %rsp = the top. push: rsp −= 8, store. pop: load, rsp += 8.
  • call: push the return address (the next instruction), jump. ret: pop into %rip.
  • Args: %rdi %rsi %rdx %rcx %r8 %r9, then the stack (8(%rsp) is arg 7 on entry). Return value in %rax. FP: %xmm0..
  • Callee-saved: %rbx %rbp %r12–%r15 (+%rsp). Caller-saved: %rax, the arg registers, %r10, %r11, all xmm.
  • Frame: return addr | saved regs | locals | argument build area. Locals go on the stack if their address is taken, or if they are arrays/structs, or if registers run out.

Solving method — stack, call/ret, frames, recursion

  1. Stack traces: keep a table with columns instruction | %rip | %rsp | top of stack | key registers. Use these rules:
    • push: rsp −= 8, then write.
    • pop: read, then rsp += 8.
    • call: push (call address + call length), then rip = target.
    • ret: rip = M[rsp], then rsp += 8.
  2. Argument location: count the integer/pointer arguments in order: %rdi, %rsi, %rdx, %rcx, %r8, %r9 (use the size-matched name, e.g. %esi for an int). Arguments 7+ are at 8(%rsp), 16(%rsp), … when the callee starts. Floating-point arguments use %xmm0, %xmm1, … with their own separate count.
  3. Locals on the stack: subq $N,%rsp allocates the space, and k(%rsp) is a local. A local goes on the stack when its address is taken (leaq k(%rsp)), or when it is an array or struct. Draw the frame from high addresses (return address) down to %rsp.
  4. Register-saving: a value needed after a call must live in a callee-saved register (rbx, rbp, r12–r15) or on the stack. Using a callee-saved register means push it in the prologue and pop it, in reverse order, in the epilogue.
  5. Recursion → C: answer four questions.
    1. Base case: which test jumps straight to ret, and what is %rax then?
    2. Saved value: what goes into %rbx (or another callee-saved register)?
    3. Recursive argument: how is %rdi changed before the call?
    4. Combine: what is done to %rax after the call?

Key facts you need for these problems
  • T A[L]: L·K bytes; &A[i] = x + K·i; A + i scales by K. No bounds checking.
  • T A[R][C] is row-major: &A[i][j] = x + K(i·C + j); a row A[i] is at x + i·C·K.
  • T *A[R] (multi-level): M[M[x + 8i] + K·j], two memory reads.
  • Fixed N → shifts and leaq; variable n → imulq.
  • Reverse-engineering dimensions: the multiplier of the first index = the column count.

Solving method — arrays

  1. Write the type size K first (char 1, short 2, int 4, long/double/any pointer 8).
  2. 1-D: &A[i] = xA + K·i. Total size = K·L.
  3. Expression tables (3.37 style): decide the type first. A pointer (A+k, &A[i]) means the value is an address and the instruction is leaq into %rax. An element (A[k], *(A+i)) means the value is M[address] and the instruction is mov with the element's suffix into the right-sized register (%ax for short, %eax for int, %rax for long).
  4. Nested T A[R][C]: &A[i][j] = xA + K·(i·C + j). Only C matters. A row A[i] starts at xA + i·C·K.
  5. Finding dimensions from assembly: annotate until you see the index expression (e.g. 7i + j). The multiplier of the first index is the number of columns of that array. Do this separately for each array.
  6. Multi-level (T *A[]): element = M[ M[xA + 8i] + K·j ], which is two memory reads.
  7. The scale must be 1, 2, 4 or 8. For K·(something) with a larger factor, the compiler first computes the index with leaq or a shift.

Unit 7 — Structures, unions, alignment, byte order, floating point

L15 · 9 practice problems · full worked solutions follow the practice set
Key facts you need for these problems
  • Struct fields are in declaration order; a K-byte primitive sits at a multiple of K; sizeof is rounded up to the largest alignment.
  • Put large fields first to save space. Arrays of structs need every element aligned.
  • Union: all fields at offset 0; size = the largest member.
  • x86 is little endian (least significant byte at the lowest address).
  • XMM0–15: FP args in %xmm0.., return in %xmm0, all caller-saved. ss/sd scalar, ps/pd packed (SIMD).

Solving method — struct layout and access

  1. Make a layout table: field | size | alignment (= size for primitives; for an array, the element size; for a nested struct, its K) | offset | padding before it.
  2. Walk the fields in order. Each offset = the next multiple of that field's alignment at or after the current end.
  3. K = the largest alignment of any field. sizeof = the end, rounded up to a multiple of K (end padding).
  4. Minimise: sort the fields by alignment, largest first, then recompute.
  5. Assembly → struct: each k(%rdi) is a field at offset k. The instruction size gives the field's size (movq = 8, movl/movslq = 4, movzwl/movw = 2, movzbl/movb = 1). A movq k(%rdi),%rdi followed by more (%rdi) accesses means you are following a pointer.
  6. Unions: size = the largest member, rounded up to the union's alignment. All offsets are 0.
  7. FP: count the FP args in %xmm0.. separately from the integer args in %rdi... The result is in %xmm0. s = single (float), d = double, p = packed.
