CISC 221 — Mock Test: Machine-Level Programming (x86-64)

Covers L09–L15 (including L14 arrays): data movement, addressing modes, arithmetic & leaq, condition codes, branches, conditional moves, loops, switch/jump tables, procedures & the stack, recursion, structs, unions, arrays, alignment and floating point.
Instructions. This mock is deliberately longer than the real quiz (about 185 raw marks, about 2 hours) so that it hits every question type the instructor uses. Assume x86-64 Linux, GCC, AT&T syntax (op Src, Dest), and the standard calling convention: arguments in %rdi, %rsi, %rdx, %rcx, %r8, %r9 and the return value in %rax. Unless a question says otherwise, all values are 8 bytes and all numbers are hexadecimal when written with 0x. Show your work in the dashed boxes.
Part A — Multiple choice / short answer (1 mark each, 16 marks)
A1. The third integer argument of a function arrives in:
  • (a) %rcx
  • (b) %rdx
  • (c) %rsi
  • (d) %r8
Answer: (b) %rdx
Argument order: %rdi, %rsi, %rdx, %rcx, %r8, %r9. Mnemonic: "Diane's Silk Dress Costs 8 9$".
A2. %rsp = 0x7ff0. After pushq %rbp, %rsp equals: 0x7fe8
push = decrement %rsp by 8, then write to (%rsp). The stack grows toward lower addresses.
A3. Which register is callee-saved?
  • (a) %r10
  • (b) %rcx
  • (c) %rbx
  • (d) %rax
Answer: (c) %rbx
Callee-saved: %rbx, %rbp, %r12–%r15 (and %rsp is restored). Everything else (%rax, the 6 argument registers, %r10, %r11) is caller-saved.
A4. True or false: leaq sets the condition codes. False
leaq only computes an address expression; the slides say "Not set by leaq instruction." That is one reason compilers like it for arithmetic.
A5. After cmpq %rsi, %rdi, which jump is taken when %rdi > %rsi as unsigned numbers?
  • (a) jg
  • (b) ja
  • (c) jb
  • (d) jge
Answer: (b) ja
a/b (above/below) are unsigned and use CF. g/l (greater/less) are signed and use SF^OF.
A6. testq %rax, %rax followed by jle .L5 jumps exactly when: %rax ≤ 0 (signed)
test computes rax&rax = rax and sets ZF/SF; OF is cleared. jle tests (SF^OF)|ZF = SF|ZF, which means negative or zero.
A7. %rax = 0x1122334455667788. After movl $-1, %eax, %rax = 0x00000000FFFFFFFF
Any instruction that writes a 32-bit register zeroes the upper 32 bits. (movw/movb would leave the other bytes unchanged.)
A8. Which of these is not a legal scale factor S in D(Rb,Ri,S)?
  • (a) 1
  • (b) 2
  • (c) 3
  • (d) 8
Answer: (c) 3
S ∈ {1, 2, 4, 8}, matching the sizes of the primitive data types, so array indexing is a single instruction.
A9. On x86-64 the int 0x12345678 is stored at address 0x100. The byte at 0x100 is: 0x78
x86 is little endian: the least significant byte is stored at the lowest address.
A10. A function returning double leaves its result in: %xmm0
FP args go in %xmm0, %xmm1, … and the FP return value is in %xmm0. All XMM registers are caller-saved.
A11. GCC will not compile v = p ? *p : 0; with a conditional move because: cmov evaluates both sides, so *p would be dereferenced even when p is NULL
The bad cases for cmov are expensive computations, risky computations (null dereference) and side effects. Both values are always computed.
A12. Which tool turns p1.s into p1.o, and which one resolves references between .o files and libraries? assembler (as/gcc); linker (ld/gcc)
The pipeline is .c → compiler (gcc -Og -S) → .s → assembler → .o → linker (+ static libraries .a) → executable. objdump -d disassembles.
A13. "Cache size and clock frequency" belong to the: microarchitecture (not the ISA)
ISA/architecture = what the assembly programmer sees (instructions, registers). Microarchitecture = how it is implemented.
A14. What does ret do, step by step? pop the return address from (%rsp) (so %rsp += 8) and jump to it (%rip = it)
call = push the address of the next instruction, then jump to the label. ret = the reverse.
A15. The 7th integer argument, at the moment the callee starts executing, is located at: 8(%rsp)
(%rsp) holds the return address pushed by call. Arguments 7, 8, … sit just above it: 8(%rsp), 16(%rsp), …
A16. Why does a switch statement use ja (unsigned) and not jg for its range check? so a negative index looks like a huge unsigned number and also goes to default (one test covers both <0 and >max)
cmpq $6,%rdi; ja .Ldefault catches both x > 6 and x < 0, because negative numbers are huge when read as unsigned.

Part D — Moves with zero/sign extension (10 marks)
D1. src_t *sp; dest_t *dp; with sp in %rdi and dp in %rsi. Give the two instructions that implement *dp = (dest_t) *sp; using %rax (or the right part of it) as the temporary. [2 each]

Part F — Condition codes, set and compare (12 marks)
F1. %rax = 5, %rbx = 7. After cmpq %rbx, %rax give the flags, and say which jumps are taken. [6]
ZF=0 SF=1 CF=1 OF=0. Taken? jl yes jb yes jg no ja no jne yes
cmpq b,a computes a − b = 5 − 7 = −2. The result is not zero (ZF=0) and is negative (SF=1). As unsigned, 5 − 7 needs a borrow (CF=1). There is no signed overflow (OF=0). jl: SF^OF = 1, taken. jb: CF = 1, taken.
F2. Give ZF, SF, CF, OF after each 1-byte add. [2]
Instruction (before: %al)ResultZF SF CF OF
addb $0x01, %al (al = 0x7F)0x800 1 0 1
addb $0x01, %al (al = 0xFF)0x001 0 1 0
0x7F + 1: 127 + 1 overflows signed (pos + pos = neg), so OF=1. There is no carry out of bit 7, so CF=0. 0xFF + 1: the carry out gives CF=1 (unsigned overflow), the result is 0 so ZF=1, and in signed terms −1 + 1 = 0 is fine, so OF=0.

Part J — Procedures, the stack, recursion (22 marks)

(b) At which offsets from %rsp do arg1 and arg2 live? arg1 at 0(%rsp), arg2 at 8(%rsp)
(c) What does caller() return? 832093
After the swap arg1 = 1057 and arg2 = 534. sum = 1591 and diff = 1057 − 534 = 523, so 1591 × 523 = 832,093. "subq $16,%rsp" allocates the frame's local storage and "addq $16,%rsp" frees it before ret. This is the same pattern as call_incr in lecture.
J3. Read the C and the assembly, then answer. [6] 
long P(long x, long y) {
  long u = Q(y);
  long v = Q(x);
  return u + v;
}
P:
  pushq %rbp
  pushq %rbx
  subq  $8, %rsp
  movq  %rdi, %rbp
  movq  %rsi, %rdi
  call  Q
  movq  %rax, %rbx
  movq  %rbp, %rdi
  call  Q
  addq  %rbx, %rax
  addq  $8, %rsp
  popq  %rbx
  popq  %rbp
  ret
(a) What do %rbp and %rbx hold during P? %rbp = x (saved for the 2nd call); %rbx = u (the 1st result)
(b) Why does P use %rbp/%rbx and not, for example, %rcx/%r10? they are callee-saved, so Q must preserve them; Q may clobber caller-saved %rcx/%r10
(c) Why does P push them at the start and pop them in reverse order? P is itself a callee and must restore its caller's values; the stack is LIFO
Key rule: a value needed after a call must live in a callee-saved register (or on the stack). Using a callee-saved register costs a push/pop pair in the function that uses it. "subq $8" keeps %rsp 16-byte aligned at the call; it is not part of your answer here.
J4. x is in %rdi. [6]

Same structure as Practice Problem 3.35 (rfun). Each level that recurses pushes %rbx (8) and then the call pushes a return address (8), so 16 bytes per level. rprod(7) → rprod(5) → rprod(3) → rprod(1) is 3 levels, so 3 × 16 = 48 bytes. 7·5·3·1 = 105.

K3. Give the field offsets, the alignment K and the total size. Then reorder the fields to minimise the size. [5] 
struct P { char a; int b; char c; double d; short e; };
a 0 b 4 c 8 d 16 e 24 K = 8 size = 32
Minimal reordering and its size: double d; int b; short e; char a; char c; → 16 bytes
Each field's offset must be a multiple of its own size: a@0, pad 3, b@4, c@8, pad 7, d@16, e@24, ending at 26. The total must be a multiple of K = 8 (the largest field), so 26 rounds up to 32. Putting the largest types first gives 8 + 4 + 2 + 1 + 1 = 16, already a multiple of 8.
K4. struct node { int val; struct node *next; short tag[3]; }; [4]
(a) Offsets of val, next, tag, and sizeof: val 0, next 8, tag 16; sizeof = 24
(b) Write assembly for short g(struct node *n) { return n->next->tag[1]; }, with n in %rdi. 
g:
  movq   8(%rdi), %rax      # rax = n->next

The 8-byte pointer must start at a multiple of 8, so there are 4 padding bytes after val. tag ends at 22, which rounds up to 24 (K = 8). This is the same access pattern as the lecture's linked-list example (movq 24(%rdi),%rdi follows r->next).
K5. union U { char c[8]; int i[2]; double d; }; sizeof(U) = 8. The same fields as a struct: sizeof = 24 [2]
A union is as big as its largest member, and all fields start at offset 0 and share storage. In the struct: c 0–7, i 8–15, d 16–23, so 24 bytes.
K6. For double g(long n, double x, int k, float y), where does each argument arrive? [2] n: %rdi, x: %xmm0, k: %esi, y: %xmm1; result in %xmm0
What is the difference between addss, addsd and addps? scalar single (1 float), scalar double (1 double), packed single (4 floats at once, SIMD)
Integer and pointer arguments use the integer registers in order, and FP arguments use the XMM registers in their own separate order.
K7. int A[4][5]; starts at address x. [3]
sizeof(A) = 80 &A[2][3] = x + 52 A[3] (the row, used as a pointer) = x + 60
Row-major order: &A[i][j] = x + K·(i·C + j) = x + 4·(2·5 + 3) = x + 52. A row is C·K = 20 bytes, so A[3] starts at x + 60. Size = R·C·K = 4·5·4 = 80.
K8. Use reverse engineering to find the constants M and N. Here i is in %rdi and j in %rsi. [4] 
long P[M][N];
long Q[N][M];
long f(long i, long j) {
  return P[i][j] + Q[j][i];
}
f:
  leaq  (%rdi,%rdi,2), %rax
  addq  %rax, %rax
  addq  %rsi, %rax
  leaq  (%rsi,%rsi,8), %rdx
  addq  %rdi, %rdx
  movq  P(,%rax,8), %rax
  addq  Q(,%rdx,8), %rax
  ret
M = 9 N = 6
This is the same exercise as the L14 sum_element example. rax = 3i, then 6i, then 6i + j, so P's index is i·N + j and N = 6. rdx = 9j, then 9j + i, so Q's index is j·M + i and M = 9. The scale 8 confirms long elements. The row length of a [R][C] array is always C, the second dimension.
K9. int *U[3]; (each element points to an int array of 5 elements) and int G[3][5];. [3]
(a) How many memory reads does U[i][j] need, and how many does G[i][j] need? U: 2 (read the pointer U[i], then the int). G: 1 (one address computation)
(b) Write assembly for int getU(size_t i, size_t j) { return U[i][j]; }, with i in %rdi and j in %rsi. 
getU:
  salq  $2, %rsi             # 4*j
  addq  U(,%rdi,8), %rsi     # p = U[i] + 4*j     (1st memory read: the pointer)
  movl  (%rsi), %eax         # return *p           (2nd memory read: the int)
  ret
A multi-level array element is at Mem[Mem[U + 8i] + 4j]. A nested array element is at Mem[G + 20i + 4j]. The two look the same in C but compile very differently.
