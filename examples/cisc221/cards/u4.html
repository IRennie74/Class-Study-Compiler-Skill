M1Find and classify the loop

How it's asked
(Practice Problem 3.26 part A style) Which loop translation did the compiler use? 
fun:   movl  $0, %eax
       jmp   .L5
.L6:   xorq  %rdi, %rax
       shrq  %rdi
.L5:   testq %rdi, %rdi
       jne   .L6
       ret
The answer, written exactly like this
Back-edge: jne .L6 (it jumps to an EARLIER label, so that is the loop).
Before the loop body there is an unconditional jmp .L5 to the test at the bottom.
→ jump-to-middle translation of a while loop (gcc -Og).
How it works

Assembly has no loop keywords. A loop is simply a jump backwards (the back-edge) that repeats some code while a condition holds. There are three standard shapes. You must recognise them because each one maps to a different C form:

ShapeGoto formRecognise it by
do-whileloop: Body; if (Test) goto loop;the body comes first, and the only test is at the bottom
while, jump-to-middle (-Og)goto test; loop: Body; test: if (Test) goto loop;an unconditional jmp to the test before the body
while, guarded-do (-O1)if (!Test) goto done; loop: Body; if (Test) goto loop; done:the test appears twice: a guard before the loop and the test at the bottom

Why do the while forms exist? A while loop may run zero times, so the test must happen before the first iteration. Jump-to-middle does that by jumping to the bottom test first. Guarded-do does it with a separate test up front, then runs a do-while (which can be faster).

Every time, do this
  1. Circle the jump to an earlier label (the back-edge).
  2. Look at what comes before the loop label: nothing, a jmp to the test, or a test that jumps past the loop.
  3. Name it: do-while, jump-to-middle or guarded-do.

M2Label the parts and write the C

How it's asked
(Practice Problem 3.24 style) Fill in long result = __; while (__) { result = __; a = __; } return result; for the code below, where a is in %rdi and b in %rsi. 
loop:  movl  $0, %eax
       jmp   .L2
.L3:   addq  %rsi, %rax
       addq  $3, %rdi
.L2:   cmpq  %rsi, %rdi
       jl    .L3
       ret
The answer, written exactly like this
movl $0,%eax            INIT     result = 0
jmp .L2                 (jump-to-middle)
.L3: addq %rsi,%rax     BODY     result = result + b
     addq $3,%rdi       UPDATE   a = a + 3
.L2: cmpq %rsi,%rdi     TEST     a : b
     jl .L3             back-edge taken while a < b   → while (a < b)

long result = 0;  while (a < b) { result = result + b;  a = a + 3; }  return result;
How it works

Every loop has four parts. Labelling them turns the assembly into C almost mechanically:

  • INIT: instructions before the loop that set starting values.
  • TEST: the compare plus the back-edge jump. The back-edge is taken when the loop continues, so the back-edge's condition is the C loop condition. (Contrast if-statements, where the jump is the negation, Unit 3 M5. A guard before a guarded-do loop is also negated.) Remember that cmp b,a reads as "a ? b".
  • UPDATE: the change to the loop variable, usually just before the test.
  • BODY: everything else inside the loop.

Then write INIT; while (TEST) { BODY; UPDATE; }. If one variable is initialised, tested and updated, you can write it as for (INIT; TEST; UPDATE) BODY.

Every time, do this
  1. Annotate the lines and mark INIT / BODY / UPDATE / TEST.
  2. Read the back-edge condition as "a ? b": that is the while condition.
  3. Write the while (or for), then check it with M3.

M3Iteration table and "what does it compute?"

How it's asked
(Practice Problem 3.26 part C style) For the fun code in M1 (x is unsigned): write the C, and describe in English what the function computes.
The answer, written exactly like this
long fun(unsigned long x) { long val = 0; while (x) { val ^= x; x >>= 1; } return val; }
Trace x = 6 (110₂):   iter   x      val (after val ^= x)
                      1      110    110
                      2      011    101
                      3      001    100
                      stop   000    → returns 100₂ = 4
Bit 0 of val is the XOR of all the bits of x: 0 ^ 1 ^ 1 = 0.
(Practice Problem 3.26 then does "return val & 1": the PARITY of x,
 1 if x has an odd number of 1-bits, 0 if even.)
How it works

When a question asks "what does this compute?", the code usually implements a well-known small algorithm. Tracing 2–3 small inputs in a table (one row per iteration: the variables plus whether the test passes) reveals the pattern. Typical patterns in this course:

  • x & 1 + x >>= 1 in a loop → working through x bit by bit (popcount = number of 1s, parity, bit length, trailing zeros).
  • val = (val << 1) | (x & 1) → reversing bits (Practice Problem 3.28).
  • result *= a with a counter → powers or factorials. result += … → sums.

State the answer in plain English, and back it up with your trace ("e.g. f(6) = …").

Every time, do this
  1. Write the C first (M2).
  2. Trace small inputs in a table.
  3. Name the pattern in one sentence, and quote one traced example.

M4Loop edge cases

How it's asked
(Practice Problem 3.28 part B style) This code has neither a test before the loop nor a jump to the middle. Explain why. 
movl $32,%edx ; movl $0,%eax
.L2: ... body ... ; subq $1,%rdx ; jne .L2 ; ret          # for (i = 32; i != 0; i--)
The answer, written exactly like this
The loop is for (i = 32; i != 0; i--). Its first test (32 != 0) is always true, so the
compiler knows the body runs at least once. The guard (or jump-to-middle) is only
needed when the loop might run zero times, so it was removed: the loop became a
plain do-while.
How it works

Small details change what a loop does, and questions test them:

  • A do-while always runs the body at least once. For an input that fails the test immediately (n = 0, a negative number), the do-while still gives one iteration's result, while a while loop gives the initial value.
  • A guard can disappear. If the compiler can prove the first test is true (a constant start like i = 32), it drops the guard, and the code looks like a do-while even though the C was a for or while.
  • Early-exit tests before a loop (e.g. if (x == 0) return 0;) can look like a guard. Check whether the same test reappears at the bottom.
  • The compiler can rewrite the test: i < 5 may become i <= 4 (jbe/jle), and unsigned loop variables use unsigned jumps.
Every time, do this
  1. Ask: could this loop run zero times? Is that case handled before the loop?
  2. Test one input that fails immediately.
  3. If a guard is "missing", look for a constant start value that makes the first test true.

M5C loop → goto → assembly

How it's asked
For long sum(long n) { long s = 0; for (long i = 1; i <= n; i++) s += i; return s; }, write (a) the while version, (b) the jump-to-middle goto version, and (c) the -Og assembly.
The answer, written exactly like this
(a) long s = 0; long i = 1;          (c) sum:                    # n in %rdi
    while (i <= n) { s += i; i++; }        movl  $0, %eax          # s = 0
(b) long s = 0; long i = 1;                  movl  $1, %edx          # i = 1
    goto test;                               jmp   .L2               # goto test
  loop:                                  .L3: addq  %rdx, %rax          # s += i
    s += i;  i++;                            addq  $1, %rdx          # i++
  test:                                  .L2: cmpq  %rdi, %rdx          # i : n
    if (i <= n) goto loop;                   jle   .L3               # if i ≤ n loop
    return s;                                ret
How it works

Going from C to assembly follows the same templates in reverse. A for loop is first rewritten as Init; while (Test) { Body; Update; } (the lecture's pcount_for → pcount_for_while). The while is then put into one of the goto shapes (M1). Each goto line maps to one or two instructions:

  • goto test → jmp .Ltest.
  • if (Test) goto loop → cmp + a jump whose condition is the test itself (not negated, because the back-edge is taken when the loop continues).
  • For guarded-do, the guard is if (!Test) goto done → cmp + the negated jump.

Keep each C variable in one register throughout, and comment every line.

Every time, do this
  1. for → while (Init; while (Test) { Body; Update; }).
  2. while → goto (jump-to-middle for -Og, guarded-do for -O1).
  3. Translate line by line, choosing registers and the jump letters (test = back-edge, !test = guard).

M6Switch: offset and range

How it's asked
A switch on x (in %rdi) starts like the code below. What are the smallest and largest case values, and which values of x go straight to the default? 
subq $100, %rdi ; cmpq $5, %rdi ; ja .Ldef ; jmp *.T(,%rdi,8)
The answer, written exactly like this
subq $100 → index = x − 100 → smallest case = 100
cmpq $5 ; ja → index 0..5 valid → largest case = 100 + 5 = 105
Straight to default: x < 100 (x − 100 is negative = huge unsigned → ja) and x > 105.
(Values 100..105 whose table entry is .Ldef also reach the default; see M7.)
How it works

For a switch with many cases close together, GCC builds a jump table: an array of 8-byte code addresses, one for each possible value. It then jumps through it in one instruction, jmp *.T(,%rdi,8) (an indirect jump: fetch the address from memory at .T + 8·index and go there). That is faster than a chain of if-else tests.

For that to work, the index must be a valid array index, 0 … n:

  • If the smallest case isn't 0, the compiler first subtracts it (subq $100, or leaq −100(%rdi), or addq for negative cases).
  • Then cmpq $n ; ja default rejects anything above n. Because ja is unsigned, a negative index looks like a huge number and is rejected by the same single test.
  • The scale is 8 because each table entry is an 8-byte address.
Every time, do this
  1. Offset k = the subtracted constant (0 if none) → smallest case = k.
  2. Largest = (the cmp constant) + k.
  3. Default: everything outside [k, max], plus the table entries pointing at the default label.

M7Switch: mapping table

How it's asked
The table for the M6 switch is .T: .quad .L3, .Ldef, .L4, .L3, .Ldef, .L5. Which cases exist, which share code, and which are missing?
The answer, written exactly like this
index   case (index + 100)   label
0       100                  .L3
1       101                  .Ldef   ← missing (goes to default)
2       102                  .L4
3       103                  .L3     ← shares code with 100
4       104                  .Ldef   ← missing
5       105                  .L5
Cases: 100, 102, 103, 105.  Shared: 100 & 103.  Missing: 101, 104.
How it works

The jump table has one entry for every value in the range, even the values with no case. Those entries hold the default label, which is how you spot a missing case. When two or more case labels share code in C (case 100: case 103: …), their entries hold the same label.

The mapping table (index → case value → label) is the single most useful thing to write for any switch question. Everything else is read off it.

Every time, do this
  1. One row per table entry: index, case = index + k, label.
  2. Mark the default-label rows as missing, and repeated labels as shared.

M8Switch: translate the blocks

How it's asked
The M6/M7 switch is in long sw(long x, long y) (y in %rsi), with the blocks below. Write the switch, and give sw(100, 4) and sw(102, 4). 
.L3:   leaq  (%rsi,%rsi,2), %rax     # case 100, 103
       ret
.L4:   addq  $1, %rsi                # case 102
.L5:   movq  %rsi, %rax              # case 105
       salq  $2, %rax
       ret
.Ldef: movl  $0, %eax
       ret
The answer, written exactly like this
.L3:   rax = 3y ; ret                       → case 100: case 103: return 3*y;
.L4:   y = y + 1 ; no jmp/ret → falls into .L5  → case 102: y++;  /* fall through */
.L5:   rax = y · 4 ; ret                     → case 105: return y * 4;   (y << 2)
.Ldef: rax = 0 ; ret                         → default: return 0;

switch (x) {
  case 100: case 103: return 3*y;
  case 102: y++;          /* fall through */
  case 105: return y * 4;
  default:  return 0;
}
sw(100,4) = 12      sw(102,4) = (4+1)·4 = 20
How it works

Each label is the code for one case (or a group of shared cases). Translate it like any straight-line code (Unit 2). The special thing to look for is fall-through: in C, a case without break keeps running into the next case. In assembly that shows up as a block with no jmp or ret at its end, placed just before the next case's label, so execution simply continues into it (.L4 → .L5 above). A break becomes a jmp to the end (or a ret).

Watch for blocks that use a register whose value was set earlier. In Practice Problem 3.31, case 4 jumps straight to the final store, so the value it stores is whatever was already in the register (the parameter a).

Every time, do this
  1. Use the mapping table (M7) to attach case numbers to labels.
  2. Translate each block, and mark every block that has no jmp/ret as a fall-through.
  3. Write the switch, then evaluate the given inputs by following the table.
