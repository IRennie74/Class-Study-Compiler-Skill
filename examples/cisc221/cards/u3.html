M1Flags after cmp

How it's asked
%rax = 4, %rbx = 6. After cmpq %rbx,%rax, give ZF, SF, CF and OF, and say whether jl, jb, jg and jne jump.
The answer, written exactly like this
cmpq %rbx,%rax computes rax − rbx = 4 − 6
Signed view:    4 − 6 = −2   → not zero: ZF=0 · negative: SF=1 · in range: OF=0
Unsigned view:  4 − 6 needs a borrow (4 < 6) → CF=1
ZF=0  SF=1  CF=1  OF=0
jl  (SF^OF = 1)       taken     (4 < 6 signed)
jb  (CF = 1)          taken     (4 < 6 unsigned)
jg  (~(SF^OF)&~ZF)    not taken
jne (~ZF)             taken
How it works

The CPU keeps four 1-bit condition codes describing the result of the last arithmetic or logic instruction (but not leaq):

FlagSet to 1 when …Used for
ZF zerothe result is 0== and !=
SF signthe result's top bit is 1 (negative as signed)signed compares
OF overflowthe true signed answer doesn't fit (pos − neg = neg, or neg − pos = pos)signed compares
CF carryan unsigned carry/borrow out of the top bitunsigned compares

cmp b,a does the subtraction a − b, sets the flags, and throws the result away. The CPU doesn't know whether your numbers are signed, so it sets both kinds of flags and the jump instruction picks the right ones. That is why you compute the subtraction in two views.

Why does "less than" use SF ^ OF? If there was no overflow, a negative result (SF=1) means a < b. If there was an overflow, the sign came out flipped, so XOR-ing with OF corrects it. test b,a works the same way but computes a & b: it sets ZF/SF, and CF/OF are 0.

Every time, do this
  1. Write "a − b" for cmp b,a (operands reversed!).
  2. Signed view → ZF, SF, OF. Unsigned view → CF.
  3. For each jump, write its flag formula, evaluate it, and say taken or not.

M2Reading cmp/test + jump/set

How it's asked
x is in %rdi. What C condition makes each jump happen? (a) cmpq $5,%rdi ; jge L (b) testq %rdi,%rdi ; je L (c) testq $1,%rdi ; jne L (d) cmpq $5,%rdi ; ja L
The answer, written exactly like this
(a) cmp $5,x → "x ? 5", ge signed        → x >= 5
(b) test x,x → x & x = x, je (ZF)         → x == 0
(c) test $1,x → x & 1, jne (not zero)     → x is odd   ((x & 1) != 0)
(d) cmp $5,x, a = above (unsigned)         → (unsigned) x > 5
How it works

Read cmp b,a ; jX L as "if (a X b) goto L". The second operand comes first in the C, the opposite of how it is written. The letters say which comparison is meant and how to treat the numbers:

LettersMeaningNumbers are …
e / ne== / !=either
g ge l le> ≥ < ≤signed (greater/less)
a ae b be> ≥ < ≤unsigned (above/below)
s / nsnegative / non-negativesigned

test idioms: testq %r,%r compares r with 0 (je → r == 0, js → r < 0, jg → r > 0, jle → r ≤ 0). testq $mask,%r checks bits: with mask 1, jne means the low bit is set (odd). setX %al does the same test but stores 0 or 1 instead of jumping.

Every time, do this
  1. Rewrite cmp b,a as "a ? b", or test r,r as "r ? 0".
  2. Use the jump letter to pick the operator and signedness.
  3. Write the C condition.

M3Type and comparison from cmp + set

How it's asked
(Practice Problem 3.13 style) int comp(data_t a, data_t b) { return a COMP b; }. Give data_t and COMP for: (A) cmpw %si,%di ; setl %al (B) cmpb %sil,%dil ; setae %al (C) cmpq %rsi,%rdi ; sete %al
The answer, written exactly like this
     size (suffix)    signedness (letter)     data_t                      COMP
(A)  w = 2 bytes      l = signed less         short                       <
(B)  b = 1 byte       ae = unsigned ≥         unsigned char               >=
(C)  q = 8 bytes      e = either              long, unsigned long, ptr    ==
How it works

A compare instruction keeps two pieces of the C type: the size (in the suffix and register names: b = char, w = short, l = int, q = long or pointer) and, through the condition letter, the signedness (g/l family = signed, a/b family = unsigned). Equality (e/ne) is the same for both, so for those you must list both types, plus pointers for q.

The comparison is read backwards: cmp %si,%di compares di (a) to si (b), so setl means a < b.

Every time, do this
  1. Suffix → size → candidate types.
  2. Letter → signed, unsigned or either → narrow the types.
  3. Write COMP from the letter, reading a ? b.

M4C comparison → assembly

How it's asked
Write the assembly for int ge(unsigned long a, unsigned long b) { return a >= b; }.
The answer, written exactly like this
ge:                       # a in %rdi, b in %rsi
  cmpq   %rsi, %rdi       # compare a : b   (computes a − b)
  setae  %al              # al = (a ≥ b), unsigned → "above or equal"
  movzbl %al, %eax        # zero-extend: rax = 0 or 1
  ret
How it works

A comparison used as a value (not in an if) compiles to three steps: compare, set a byte, widen.

  • cmp, sized to the type (cmpq for 8 bytes, cmpl for int …). Put b first and a second so the condition reads a ? b.
  • setX writes 0 or 1 into a single byte register (%al), choosing the letter by operator and signedness (unsigned ≥ → ae, signed ≥ → ge).
  • movzbl %al,%eax: setX changes only 1 byte, but the return value is all of %rax. movzbl zero-extends the byte to 32 bits, and the 32-bit write also clears the top half (Unit 1 M4).

This is the lecture's gt example: cmpq %rsi,%rdi ; setg %al ; movzbl %al,%eax.

Every time, do this
  1. cmp b,a, with the right size.
  2. setX: the operator plus the signed/unsigned letter.
  3. movzbl %al,%eax, then ret.

M5if / else-if → C

How it's asked
Fill in the C. Here x is in %rdi and y in %rsi. 
long f(long x, long y) {
  long val = ______;
  if (______)
    val = ______;
  else if (______)
    val = ______;
  return val;
}
f:
  leaq  (%rdi,%rsi), %rax
  cmpq  %rsi, %rdi
  jle   .L2
  movq  %rdi, %rax
  subq  %rsi, %rax
  ret
.L2:
  testq %rdi, %rdi
  jns   .L3
  negq  %rdi
  movq  %rdi, %rax
.L3:
  ret
The answer, written exactly like this
Map: x → %rdi, y → %rsi
leaq (%rdi,%rsi),%rax     rax = x + y                        ⇒ val = x + y
cmpq %rsi,%rdi ; jle .L2  jump if x ≤ y │ fall-through x > y ⇒ if (x > y)
  rax = x ; rax = x − y ; ret                                ⇒   val = x - y;
.L2: testq x,x ; jns .L3  jump if x ≥ 0 │ fall-through x < 0 ⇒ else if (x < 0)
  rdi = −x ; rax = −x                                        ⇒   val = -x;
.L3: ret                                                     ⇒ return val;

long val = x + y;
if (x > y) val = x - y;
else if (x < 0) val = -x;
return val;
Check: (5,1) → 4 ✓   (−3,2) → 3 ✓   (1,2) → 3 ✓ (no branch taken)
How it works

Assembly has no if statement, only conditional jumps. The compiler lays out the code as blocks and uses jumps to skip the blocks that shouldn't run:

if (Test) Then; else Else;      becomes      if (!Test) goto Else;
                                             Then; goto Done;
                                         Else: Else;
                                         Done:

The key consequence: the jump tests the opposite of the C condition, because it jumps past the then-block. So the C condition is the fall-through condition. In the example, jle .L2 skips the block when x ≤ y, so the block's C test is x > y.

Other patterns: a value computed before the first test is the variable's initial value. Each ret (or jmp to the end) ends one path. An else-if shows up as another test at the jump target. A missing else just means the false edge jumps straight to the end. Practice Problem 3.18 (nested ifs) is the full version of this, and it was the centrepiece of the revision video.

Every time, do this
  1. Annotate every line; anything before the first test is the initial value.
  2. For each conditional jump, write both edges: "jump if …" and "fall-through …".
  3. The fall-through condition is the C if-test. Fill the template, then check one input per path.

M6Reading cmov

How it's asked
Fill in long g(long x, long y) { return ____ ? ____ : ____; } 
g:  leaq   (%rdi,%rsi), %rax
    movq   %rdi, %rdx
    imulq  %rsi, %rdx
    cmpq   $10, %rdi
    cmovg  %rdx, %rax
    ret
The answer, written exactly like this
rax = x + y           ← default value
rdx = x · y           ← alternative
cmpq $10,%rdi ; cmovg → if x > 10, rax = x · y
return x > 10 ? x * y : x + y;
How it works

A conditional move cmovX src,dst copies src into dst only if condition X holds. Otherwise dst is unchanged. The compiler uses it for simple ?: and if/else assignments:

result = Then_value;  eval = Else_value;  if (!Test) result = eval;

Both values are computed first, and the cmov then picks one, with no jump. That matters for speed: modern CPUs work on many instructions at once (a pipeline), and a mispredicted jump forces them to throw that work away. cmov has no jump to mispredict.

To read it: the value already in the destination is the default, and the cmov condition chooses the other value. So the C is condition ? cmov-source-value : default. Watch out: the compiler may compute the "else" value first and cmov in the "then" value, or the reverse (Practice Problem 3.21).

Every time, do this
  1. Annotate what each register holds before the cmp.
  2. Find which register the cmov writes: its old value is the default.
  3. Write: cmov condition ? source value : default.

M7When cmov cannot be used

How it's asked
For each, say whether GCC could compile it with a conditional move, and why: (a) v = x > y ? x - y : y - x; (b) v = p ? *p : 0; (c) v = x > 0 ? x *= 7 : x += 3; (d) v = t ? slow1(x) : slow2(x);
The answer, written exactly like this
(a) yes: both values are cheap and safe to compute
(b) no:  cmov computes both sides, so *p would be read even when p == NULL (crash)
(c) no:  both sides would run, changing x twice (side effects)
(d) no:  both expensive calls would run (and they may have side effects)
How it works

cmov always evaluates both the then-value and the else-value before it chooses. That is only correct if computing the unused value is harmless. The lecture lists three bad cases:

  • Risky computations, which could crash (null pointer dereference).
  • Side effects, which change state (assignments, ++, function calls).
  • Expensive computations, where doing both costs more than a mispredicted branch.

In those cases the compiler uses ordinary branches (M5) instead.

Every time, do this
  1. Imagine computing both sides every time.
  2. Could that crash, change state, or be slow? Then no cmov.
  3. Name the reason (risky, side effect or expensive).

M8&& / || short-circuit

How it's asked
(Practice Problem 3.16 style) For void cap(long *p, long m) { if (p && *p < m) *p = m; }: (A) write a goto version that follows the assembly's control flow; (B) explain why there are two conditional branches.
The answer, written exactly like this
(A) void cap_goto(long *p, long m) {
      if (p == 0) goto done;        // testq %rdi,%rdi ; je done
      if (*p >= m) goto done;       // cmpq %rsi,(%rdi) ; jge done
      *p = m;
    done:
      return;
    }
(B) && short-circuits: if p is null, the second test (*p < m) must not run,
    so each operand gets its own test and branch.
How it works

In C, A && B evaluates B only if A is true, and A || B evaluates B only if A is false. This is "short-circuit" evaluation, and code relies on it: p && *p is safe exactly because *p is never read when p is null.

So the compiler cannot compute both and combine them. It must test A, jump away if A already decides the answer, and only then test B. For &&, each false operand jumps to "skip". For ||, each true operand jumps to "do it". Each jump tests the negation (M5): "if p == 0 goto done".

Every time, do this
  1. Write one if (!operand) goto done; per operand of && (for ||: if (operand) goto body;).
  2. Then the body, then the done label.
  3. Explain in one line: short-circuit evaluation.

M9C → goto form → branch assembly

How it's asked
Write the goto version, then the branching assembly, for long m(long a, long b) { long r; if (a < b) r = b; else r = a - b; return r; }
The answer, written exactly like this
long m_goto(long a, long b) {        m:                     # a in %rdi, b in %rsi
  long r;                              cmpq %rsi, %rdi      # a : b
  if (a >= b) goto Else;  // !test     jge  .L2             # a ≥ b → Else
  r = b;                               movq %rsi, %rax      # r = b
  goto Done;                           ret
Else:                                .L2:
  r = a - b;                           movq %rdi, %rax
Done:                                  subq %rsi, %rax      # r = a − b
  return r;                            ret
}
How it works

The "goto version" is C written the way the machine runs it: no if/else blocks, only conditional jumps and labels. The lecture's template is ntest = !Test; if (ntest) goto Else; Then; goto Done; Else: Else; Done:.

Writing it is the bridge to assembly. Each if (cond) goto L becomes one cmp + jX L, with the letter for the negated test (a < b becomes jge). Each label becomes an assembly label. goto Done followed by return usually becomes a ret straight away.

Every time, do this
  1. Negate the test: if (!Test) goto Else.
  2. Then-block, goto Done, then Else: block, then Done:.
  3. Translate: cmp b,a + the negated jump letter; each block ends in ret (or jmp to Done).

M10Divide by 2k (bias idiom)

How it's asked
(Practice Problem 3.20 style) #define OP ___ · long arith(long x) { return x OP 16; } compiles to the code below. What is OP? Annotate each line. 
leaq 15(%rdi),%rax ; testq %rdi,%rdi ; cmovns %rdi,%rax ; sarq $4,%rax ; ret
The answer, written exactly like this
OP is /   (x / 16)
leaq 15(%rdi),%rax    temp = x + 15            bias = 2⁴ − 1 for negative x
testq ; cmovns        if x ≥ 0: temp = x       no bias needed when x is non-negative
sarq $4,%rax          temp >> 4 = temp / 16    arithmetic shift (x is signed)
How it works

Shifting right by k divides by 2k, but sar rounds down (toward −∞): −17 >> 4 = −2. C requires division to round toward zero: −17 / 16 = −1. For non-negative x the two agree. For negative x the compiler first adds a bias of 2k − 1, which pushes the value up just enough that the shift rounds toward zero: (−17 + 15) >> 4 = −2 >> 4 = −1 ✓.

The test/cmovns pair chooses: if x is not signed-negative, use plain x, otherwise use x + bias. So whenever you see "add 2k−1, cmov on sign, sar k", the operator is division by 2k.

Every time, do this
  1. Find the shift amount k, and check that the leaq constant is 2k − 1.
  2. OP = /, by 2k.
  3. Annotate: bias, choose by sign, shift.
