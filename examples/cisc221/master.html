B. Lecture-by-lecture notes

L09 — Machine-Level Programming I: Fundamentals (part 1)

  • Why learn machine code: to understand compiler optimisation and its limits, to understand run-time behaviour, and to understand vulnerabilities (and defend against them).
  • History: x86 dominates laptops, desktops and servers. It is an evolutionary design, backward compatible to the 8086 (1978), and a CISC (many instructions and formats, of which Linux programs use a small subset). Transistor counts: 386 (1985) 0.3M → Pentium 4 (2001) 42M → Core i7 (2008) 731M → Core i7/i9 (~2020) 2–4 billion; the Apple A15 (2021) has 15 billion. Features added over time: multimedia instructions, conditional-operation instructions (cmov), the move from 32 to 64 bits, more cores.
  • Definitions: Architecture/ISA = the parts of the processor design you need to understand to write assembly or machine code (instruction set, registers). Microarchitecture = the implementation (cache sizes, core frequency). Machine code = the bytes. Assembly = their text form. Example ISAs: Intel x86, IA32, Itanium, x86-64; ARM.
  • Programmer-visible state: PC (%rip, the address of the next instruction), the register file, the condition codes (status of the last arithmetic/logic op, used for branching), and memory (a byte-addressable array holding code, user data and the stack).
  • Toolchain: gcc -Og p1.c p2.c -o p. Compiler (gcc -Og -S) → .s; assembler (gcc or as) → .o; linker (gcc or ld) combines the .o files with static libraries (.a) to make the executable. Some libraries are dynamically linked, which happens when the program starts executing. The warning: results differ on non-CASLab machines because of the GCC version and settings.
  • Example used throughout: 
    long plus(long x, long y);
void sumstore(long x, long y, long *dest) { long t = plus(x, y); *dest = t; }

sumstore:                       0x400595: 53              push %rbx
  pushq %rbx                    0x400596: 48 89 d3        mov %rdx,%rbx
  movq  %rdx, %rbx              0x400599: e8 f2 ff ff ff  callq 400590 <plus>
  call  plus                    0x40059e: 48 89 03        mov %rax,(%rbx)
  movq  %rax, (%rbx)            0x4005a1: 5b              pop %rbx
  popq  %rbx                    0x4005a2: c3              retq
  ret                           (14 bytes; instructions are 1, 3 or 5 bytes here)
    *dest = t; becomes movq %rax,(%rbx): t is in %rax, dest is in %rbx, and *dest is M[%rbx]. Encoded as the 3 bytes 48 89 03 at 0x40059e.
  • Assembly data types: "integer" data of 1, 2, 4 or 8 bytes (values or untyped addresses); floating point of 4, 8 or 10 bytes; code = byte sequences. No aggregate types: arrays and structs are just contiguous bytes. Operations: move data between memory and registers (load/store), arithmetic on registers or memory, and transfer of control (jumps, calls, conditional branches).
  • Disassembly: objdump -d sum (works on a.out or .o files) or, in gdb, disassemble sumstore and x/14xb sumstore (examine 14 bytes).
  • Registers: 16 64-bit registers: %rax, %rbx, %rcx, %rdx, %rsi, %rdi, %rsp, %rbp, %r8–%r15. The low 4, 2 and 1 bytes are addressable (%eax/%ax/%al; %r8d/%r8w/%r8b). IA32 origins: accumulator, counter, data, base, source index, destination index, stack pointer, base pointer.
  • movq Source, Dest with operand types Immediate ($0x400, $-533), Register (%rsp is reserved for special use), and Memory (8 consecutive bytes at the address in a register, e.g. (%rax)). Legal combinations: Imm→Reg (temp = 0x4), Imm→Mem (*p = -147), Reg→Reg, Reg→Mem (*p = temp), Mem→Reg (temp = *p). No memory-to-memory move in a single instruction.
  • Simple addressing: Normal (R) = Mem[Reg[R]] (pointer dereference); Displacement D(R) = Mem[Reg[R] + D].
  • swap example: 
    void swap(long *xp, long *yp) { long t0 = *xp; long t1 = *yp; *xp = t1; *yp = t0; }
swap:
  movq (%rdi), %rax    # t0 = *xp
  movq (%rsi), %rdx    # t1 = *yp
  movq %rdx, (%rdi)    # *xp = t1
  movq %rax, (%rsi)    # *yp = t0
  ret
    Trace: %rdi = 0x120 (M = 123) and %rsi = 0x100 (M = 456). After the swap, M[0x120] = 456 and M[0x100] = 123.

L10 — Fundamentals (part 2): addressing, leaq, arithmetic

  • Register discipline story (repeated in L11 and L13): main sets x = 10 and y = 20 and calls fun1(x, y). Before the call it moves x to %rdi and y to %rsi, and must "make sure that x and y are safe". After the call it receives c in %rax and retrieves x and y. Inside fun1, a arrives in %rdi and b in %rsi. Before fun1 calls fun2(c, d), it must move c to %rdi and d to %rsi, which overwrites its own arguments. L13 gives the fix: keep x and y in callee-saved registers (%rbx, %r12).
  • Full addressing mode: D(Rb,Ri,S) = Mem[Reg[Rb] + S·Reg[Ri] + D]. Rb is any of the 16 registers; Ri is any except %rsp; S is 1, 2, 4 or 8 ("why these numbers?" because they are the data type sizes). Special cases: (Rb,Ri), D(Rb,Ri), (Rb,Ri,S).
  • Address computation examples (%rdx = 0xf000, %rcx = 0x0100): 0x8(%rdx) = 0xf008; (%rdx,%rcx) = 0xf100; (%rdx,%rcx,4) = 0xf400; 0x80(,%rdx,2) = 0x1e080.
  • Invalid moves slide: movb $0xF,(%ebx) (cannot use %ebx as an address register; addresses are 64-bit); movl %rax,(%rsp) (suffix/register size mismatch); movq (%rax),4(%rsp) (memory to memory); movq %rax,$0x123 (immediate destination); movl %rax,%erp (wrong destination size / bad register).
  • leaq Src, Dst: Src is an address-mode expression, and Dst gets the address it denotes. Used to compute addresses without a memory reference (p = &x[i]) and to compute x + k·y with k = 1, 2, 4 or 8. long m12(long x){return x*12;} becomes leaq (%rdi,%rdi,2),%rax (t = x + 2x) then salq $2,%rax (t << 2).
  • Two-operand arithmetic: addq, subq (Dest = Dest − Src), imulq, salq (= shlq), sarq (arithmetic), shrq (logical), xorq, andq, orq. "Watch out for argument order!" There is no distinction between signed and unsigned int for add/sub/imul, because two's-complement bit patterns behave the same. One-operand: incq, decq, negq, notq.
  • arith example: 
    long arith(long x, long y, long z) {
  long t1 = x+y; long t2 = z+t1; long t3 = x+4; long t4 = y*48;
  long t5 = t3+t4; long rval = t2*t5; return rval; }
arith:
  leaq  (%rdi,%rsi), %rax     # t1
  addq  %rdx, %rax            # t2
  leaq  (%rsi,%rsi,2), %rdx
  salq  $4, %rdx              # t4
  leaq  4(%rdi,%rdx), %rcx    # t5
  imulq %rcx, %rax            # rval
  ret
    Register uses: %rdi = x, %rsi = y, %rdx = z then t4, %rax = t1, t2, rval, %rcx = t5. "imulq: only used once"; leaq and salq do the rest.

L11 — Machine-Level Programming II: Control

  • Processor state: temporary data (%rax …), the runtime stack location (%rsp), the current code location (%rip), and the status of recent tests (CF, ZF, SF, OF).
  • Implicit setting by arithmetic (e.g. addq Src,Dest computing t = a + b): CF = carry out of the MSB (unsigned overflow); ZF = (t == 0); SF = (t < 0 as signed); OF = two's-complement overflow: (a>0 && b>0 && t<0) || (a<0 && b<0 && t>=0). Not set by leaq.
  • cmpq Src2, Src1: cmpq b,a works like computing a − b without storing it. CF for unsigned comparisons; ZF if a == b; SF if (a − b) < 0; OF on signed overflow: (a>0 && b<0 && (a−b)<0) || (a<0 && b>0 && (a−b)>0).
  • testq Src2, Src1: testq b,a works like a & b without storing it. Useful with one operand as a mask. ZF when a & b == 0; SF when a & b < 0.
  • Three ways to read the condition codes: (1) setX (set a single byte), (2) conditional jumps jX, (3) conditional data transfer cmovX.
  • setX table: sete ZF; setne ~ZF; sets SF; setns ~SF; setg ~(SF^OF)&~ZF; setge ~(SF^OF); setl SF^OF; setle (SF^OF)|ZF; seta ~CF&~ZF; setb CF. setX writes the low byte of the destination and does not alter the other 7 bytes, so it is typically followed by movzbl (and 32-bit instructions zero the upper 32 bits). The byte registers are %al, %bl, %cl, %dl, %sil, %dil, %spl, %bpl, %r8b–%r15b. 
    int gt(long x, long y) { return x > y; }
  cmpq   %rsi, %rdi    # Compare x:y
  setg   %al           # Set when >
  movzbl %al, %eax     # Zero rest of %rax
  ret
  • jX table: jmp (always), je, jne, js, jns, jg, jge, jl, jle, ja, jb, with the same conditions as setX.
  • Old-style branch (gcc -Og -S -fno-if-conversion control.c): absdiff with cmpq %rsi,%rdi; jle .L4; then x − y; .L4: y − x. The goto version is used to illustrate assembly structure: ntest = x <= y; if (ntest) goto Else; result = x-y; goto Done; Else: result = y-x; Done: return result;. General form: val = Test ? Then : Else becomes ntest = !Test; if (ntest) goto Else; val = Then; goto Done; Else: val = Else; Done:.
  • Conditional moves: if (Test) Dest ← Src, available on x86 processors since 1995. GCC uses them only when it is known to be safe. Why: branches are very disruptive to the instruction flow through pipelines, and cmov needs no control transfer. Goto version: result = Then_Expr; eval = Else_Expr; nt = !Test; if (nt) result = eval; return result;. absdiff with cmov: movq %rdi,%rax; subq %rsi,%rax; movq %rsi,%rdx; subq %rdi,%rdx; cmpq %rsi,%rdi; cmovle %rdx,%rax; ret.
  • Bad cases for cmov (both values get computed): expensive computations Test(x) ? Hard1(x) : Hard2(x); risky computations p ? *p : 0; computations with side effects x > 0 ? x*=7 : x+=3.
  • Loops (popcount do-while, while as jump-to-middle (-Og) and do-while conversion (-O1), for → while → do-while; details in L12 below).
  • Switch (switch_eg, details in L12): multiple case labels (5 and 6), fall-through (2), missing cases (4). Jump table structure: goto *JTab[x].
  • Summary slide: C control (if-then-else, do-while, while, for, switch) maps to assembler control (conditional jump, conditional move, indirect jump via jump tables). Loops are converted to do-while or jump-to-middle form. Large switches use jump tables; sparse switches may use decision trees (if-elseif-else).

L12 — Machine-Level Programming III: Loops & Procedures (part 1)

  • Do-while popcount: 
    long pcount_do(unsigned long x) {           movl $0, %eax        # result = 0
  long result = 0;                         .L2:                       # loop:
  do { result += x & 0x1; x >>= 1; }         movq %rdi, %rdx
  while (x);                                 andl $1, %edx        # t = x & 0x1
  return result;                             addq %rdx, %rax      # result += t
}                                            shrq %rdi            # x >>= 1
                                             jne  .L2             # if (x) goto loop
                                             rep; ret
    General do-while: loop: Body; if (Test) goto loop.
  • While, jump-to-middle (-Og): goto test; loop: Body; test: if (Test) goto loop; done:. For pcount_while the assembly is jmp .L3 (go to test), body, then .L3: cmpq $0,%rdi; jne .L2. Compared with do-while, the initial goto starts the loop at the test.
  • While, do-while conversion (-O1, "guarded do"): if (!Test) goto done; loop: Body; if (Test) goto loop; done:. The initial conditional guards the entrance to the loop.
  • For loop: for (Init; Test; Update) Body = Init; while (Test) { Body; Update; }. Example pcount_for with #define WSIZE 8*sizeof(int), for (i = 0; i < WSIZE; i++) { unsigned bit = (x >> i) & 0x1; result += bit; }. In the goto/do-while version, "the initial test can be optimized away" (0 < WSIZE is known to be true).
  • Switch example (also in L11): 
    long switch_eg(long x, long y, long z) {      switch_eg:
  long w = 1;                                   movq %rdx, %rcx
  switch(x) {                                   cmpq $6, %rdi         # x:6
  case 1: w = y*z; break;                       ja   .L8              # Use default
  case 2: w = y/z; /* Fall Through */           jmp  *.L4(,%rdi,8)    # goto *JTab[x]
  case 3: w += z; break;                      .section .rodata  .align 8
  case 5:                                     .L4: .quad .L8  # x = 0
  case 6: w -= z; break;                           .quad .L3  # x = 1
  default: w = 2;                                  .quad .L5  # x = 2
  }                                                .quad .L9  # x = 3
  return w;                                        .quad .L8  # x = 4
}                                                  .quad .L7  # x = 5
                                                   .quad .L7  # x = 6
.L3: movq %rsi,%rax ; imulq %rdx,%rax ; ret                     # case 1: y*z
.L5: movq %rsi,%rax ; cqto ; idivq %rcx ; jmp .L6               # case 2: y/z, goto merge
.L9: movl $1,%eax                                               # case 3: w = 1
.L6: addq %rcx,%rax ; ret                                       # merge: w += z
.L7: movl $1,%eax ; subq %rdx,%rax ; ret                        # case 5,6: w = 1 - z
.L8: movl $2,%eax ; ret                                         # default: 2
    Notes: w is not initialised in the setup (each block sets it as needed). "What range of values takes default?" x < 0 or x > 6 (the unsigned ja), plus the missing values 0 and 4 through the table. Direct jump jmp .L8 versus indirect jump jmp *.L4(,%rdi,8): the table starts at .L4, entries are scaled by 8 (addresses are 8 bytes), the target is fetched from .L4 + 8x, and this is only valid for 0 ≤ x ≤ 6. Fall-through handling: case 2 computes y/z and does goto merge, while case 3 sets w = 1 and then reaches merge: w += z. %rdx is copied to %rcx at the start because idivq uses %rdx.
  • Procedure mechanisms: passing control (to the start of the procedure and back to the return point), passing data (arguments and return value), and memory management (allocate during execution, deallocate on return). All are implemented with machine instructions, and x86-64 uses only the mechanisms a given procedure requires.
  • Stack: a region of memory managed with stack discipline, growing toward lower addresses. %rsp holds the lowest stack address (the top element). pushq Src: fetch the operand, decrement %rsp by 8, write at %rsp. popq Dest: read at %rsp, increment %rsp by 8, store into Dest (which must be a register).
  • multstore/mult2 code: 
    0000000000400540 <multstore>:                  0000000000400550 <mult2>:
  400540: push   %rbx            # Save %rbx      400550: mov  %rdi,%rax   # a
  400541: mov    %rdx,%rbx       # Save dest      400553: imul %rsi,%rax   # a * b
  400544: callq  400550 <mult2>  # mult2(x,y)     400557: retq             # Return
  400549: mov    %rax,(%rbx)     # Save at dest
  40054c: pop    %rbx            # Restore %rbx
  40054d: retq                   # Return
    call label: (1) push the return address (from %rip) on the stack, (2) jump to the label by changing %rip. The return address is the address of the next instruction after the call (0x400549). ret: (1) pop the address into %rip, (2) jump there. Control-flow walk-through: %rsp 0x120 and %rip 0x400544 → after call %rsp 0x118, M[0x118] = 0x400549, %rip 0x400550 → %rip 0x400557 at retq → after ret %rsp 0x120, %rip 0x400549.
  • Data flow: the first 6 arguments go in %rdi, %rsi, %rdx, %rcx, %r8, %r9; arguments 7..n go on the stack (Arg 7 nearest the top); the return value is in %rax. Stack space is only allocated when needed.
  • Stack-based languages: code must be reentrant (multiple simultaneous instances of one procedure), so each instance needs a place for its state (arguments, local variables, return pointer). The state is needed only from call to return, and the callee returns before the caller does, so the stack is allocated in frames. Call chain example: yoo → who → amI → amI (recursive).
  • Frame contents (from top to bottom of the current frame): argument build area (parameters for a function about to be called), local variables (if they cannot be kept in registers), saved register context, old frame pointer (optional, %rbp). The caller's frame holds the return address (pushed by call) and arguments 7+. Frame management: space is allocated on entry ("set-up" code, including the push by call) and freed on return ("finish" code, including the pop by ret). %rbp is optionally a frame pointer.
  • incr / call_incr example: 
    long incr(long *p, long val) { long x = *p; long y = x + val; *p = y; return x; }
incr:  movq (%rdi), %rax ; addq %rax, %rsi ; movq %rsi, (%rdi) ; ret
       # %rdi = p, %rsi = val then y, %rax = x (return value)

long call_incr() { long v1 = 15213; long v2 = incr(&v1, 3000); return v1+v2; }
call_incr:
  subq  $16, %rsp            # allocate: v1 lives at 8(%rsp)
  movq  $15213, 8(%rsp)
  movl  $3000, %esi
  leaq  8(%rsp), %rdi        # &v1
  call  incr                 # v1 becomes 18213, %rax = 15213
  addq  8(%rsp), %rax        # v1 + v2 = 18213 + 15213 = 33426
  addq  $16, %rsp
  ret
  • Register saving conventions: if yoo calls who, yoo is the caller and who is the callee. Problem: yoo puts 15213 in %rdx, calls who, and who does subq $18213,%rdx, so yoo's %rdx is overwritten. Conventions: caller saved (the caller saves temporaries in its frame before the call) and callee saved (the callee saves temporaries in its frame before using the registers and restores them before returning).
  • Linux register usage: %rax return value, caller-saved, can be modified by the procedure. %rdi … %r9: arguments, caller-saved. %r10, %r11: caller-saved temporaries. %rbx, %r12–%r15: callee-saved. %rbp: callee-saved, may be used as the frame pointer. %rsp: a special form of callee-saved (restored to its original value on exit).
  • call_incr2 (callee-saved example): long call_incr2(long x) { long v1 = 15213; long v2 = incr(&v1, 3000); return x+v2; } becomes pushq %rbx; subq $16,%rsp; movq %rdi,%rbx; movq $15213,8(%rsp); movl $3000,%esi; leaq 8(%rsp),%rdi; call incr; addq %rbx,%rax; addq $16,%rsp; popq %rbx; ret. Stack after setup: rtn address / saved %rbx / 15213 / unused ← %rsp.
  • Recursion: pcount_r (assembly given in section 14 of the concepts guide): terminal case (x == 0 returns 0 via je .L6), register save (pushq %rbx), call setup (%rdi = x >> 1, %rbx = x & 1, callee-saved), the call (%rax = recursive return value), result (addq %rbx,%rax), completion (popq %rbx; ret). Trace for x = 0110: the calls see %rdi = 0110 (rbx 0), 0011 (rbx 1), 0001 (rbx 1), 0000 (base case). The returns give %rax = 0 → 1 → 2 → 2.

L13 — Machine-Level Programming III: Procedures (Winter 2025 deck)

  • Repeats the L12 procedure content (stack, push/pop, call/ret, data flow, frames, incr, register conventions, call_incr2, pcount_r) and adds the memory layout recap (stack at the top, then shared libraries, heap, data, text).
  • main/fun1 fix: main puts x and y in callee-saved registers (%rbx and %r12) and operates on %rbx/%r12 after the call. Inside fun1, calling fun2(h, t) overwrites %rdi ← h and %rsi ← t, so fun1 must also preserve its own a and b if it still needs them.
  • Observations about recursion: it is handled without special consideration. Stack frames give each call private storage (saved registers, locals, return pointer). Register conventions prevent one call from corrupting another's data, unless the C code does so explicitly (e.g. a buffer overflow). The stack follows the call/return pattern (if P calls Q, Q returns before P: last-in, first-out). It also works for mutual recursion.
  • Procedure summary: the stack is the right data structure for call/return; values can be stored safely in the local frame and in callee-saved registers; function arguments go at the top of the stack; the result returns in %rax; pointers are addresses of values, on the stack or global.

L14 — Machine-Level Programming IV: Arrays

  • Allocation: T A[L] is a contiguous region of L·sizeof(T) bytes. Examples: char string[12] (x … x+12), int val[5] (x, x+4, …, x+20), double a[3] (x … x+24), char *p[3] (24 bytes).
  • Access: the identifier A acts as a pointer to element 0 (type T*). With int val[5] = {1,5,2,1,3}: val[4] is int 3; val is int* x; val+1 is int* x+4; &val[2] is int* x+8; val[5] is int ?? (out of bounds); *(val+1) is int 5; val+i is int* x+4i.
  • zip_dig: #define ZLEN 5; typedef int zip_dig[ZLEN]; zip_dig cmu = {1,5,2,1,3}, mit = {0,2,1,3,9}, ucb = {9,4,7,2,0}; "zip_dig cmu" is equivalent to "int cmu[5]". In the example they were allocated in successive 20-byte blocks (cmu at 16, mit at 36, ucb at 56), but this is not guaranteed in general.
  • get_digit(zip_dig z, int digit) { return z[digit]; } becomes movl (%rdi,%rsi,4), %eax (%rdi = start address, %rsi = index, desired digit at %rdi + 4·%rsi).
  • zincr loop: for (i = 0; i < ZLEN; i++) z[i]++; becomes movl $0,%eax; jmp .L3; .L4: addl $1,(%rdi,%rax,4); addq $1,%rax; .L3: cmpq $4,%rax; jbe .L4; rep; ret. This is jump-to-middle, the test is rewritten as i ≤ 4, and it uses unsigned jbe because i is size_t.
  • Nested arrays: T A[R][C] is a 2-D array with R rows and C columns, each element K bytes, R·C·K bytes in total, in row-major order. For a 3×3 matrix flattened to [1..9], a[1][2] → a[1·3 + 2] = a[5] = 6, stored at Mem[a + k·5]. In general a[i][j] → a[i·C + j] at Mem[a + k(i·C + j)].
  • pgh: #define PCOUNT 4; zip_dig pgh[PCOUNT] = {{1,5,2,0,6},{1,5,2,1,3},{1,5,2,1,7},{1,5,2,2,1}}; is equivalent to int pgh[4][5], occupying addresses 76 … 156 (20 bytes per row). Row access: A[i] is an array of C elements starting at A + i·(C·K). get_pgh_zip returns pgh[index]: leaq (%rdi,%rdi,4),%rax (5·index); leaq pgh(,%rax,4),%rax (pgh + 20·index). Element access: A[i][j] at A + i·(C·K) + j·K = A + (i·C + j)·K. get_pgh_digit: leaq (%rdi,%rdi,4),%rax; addl %rax,%rsi; movl pgh(,%rsi,4),%eax = M[pgh + 4·(5·index + dig)].
  • Multi-level array: int *univ[3] = {mit, cmu, ucb}; is an array of 3 pointers, 8 bytes each (stored at 160, 168, 176, with values 36, 16, 56), each pointing to an int array. get_univ_digit: salq $2,%rsi (4·digit); addq univ(,%rdi,8),%rsi (p = univ[index] + 4·digit); movl (%rsi),%eax. The element is at Mem[Mem[univ + 8·index] + 4·digit]: two memory reads (first get the pointer to the row array, then the element).
  • Comparison: nested Mem[pgh + 20·index + 4·digit] is a single memory access. Multi-level is a double access. The C looks identical.
  • N×N matrices: fixed dimensions (N known at compile time, typedef int fix_matrix[N][N]); variable dimensions with explicit indexing (the traditional dynamic array, #define IDX(n,i,j) ((i)*(n)+(j)), a[IDX(n,i,j)]); variable dimensions with implicit indexing (int a[n][n], now supported by gcc). Fixed 16×16 (C = 16, K = 4): salq $6,%rsi (64·i); addq %rsi,%rdi; movl (%rdi,%rdx,4),%eax. Variable n×n: must perform integer multiplication: imulq %rdx,%rdi (n·i); leaq (%rsi,%rdi,4),%rax; movl (%rax,%rcx,4),%eax.
  • Closing example ("use your reverse engineering skill to deduce N and M"): long A[M][N]; long B[N][M]; sum_element(i, j) = A[i][j] + B[j][i]. The annotated assembly gives rdx = 8i → 7i → 7i + j and rax = 5j, rdi = 5j + i. Then movq B(,%rdi,8),%rax; addq A(,%rdx,8),%rax. So N = 7, M = 5.

L15 — Machine-Level Programming IV: Data (structures, unions, floating point)

  • Structure representation: struct rec { int a[4]; size_t i; struct rec *next; }; has a at 0, i at 16, next at 24, and a size of 32. A struct is a block of memory big enough for all its fields, with the fields in declaration order even if another order would be more compact. The compiler determines the size and positions; the machine-level program has no understanding of the structs in the source.
  • Pointer to a member: int *get_ap(struct rec *r, size_t idx) { return &r->a[idx]; } becomes leaq (%rdi,%rsi,4),%rax. Offsets are fixed at compile time.
  • Linked list: void set_val(struct rec *r, int val) { while (r) { int i = r->i; r->a[i] = val; r = r->next; } } becomes .L11: movslq 16(%rdi),%rax (i = M[r+16]); movl %esi,(%rdi,%rax,4) (M[r + 4i] = val); movq 24(%rdi),%rdi (r = M[r+24]); testq %rdi,%rdi; jne .L11.
  • Alignment: for struct S1 { char c; int i[2]; double v; } *p;, the unaligned layout would be c at p, i at p+1, v at p+9 (17 bytes). The aligned layout is c at p+0, 3 bytes of padding, i[0] at p+4, i[1] at p+8, 4 bytes of padding, v at p+16, for 24 bytes. Principle: a primitive of K bytes must have an address that is a multiple of K. This is required on some machines and advised on x86-64. Motivation: memory is accessed in aligned chunks of 4 or 8 bytes, it is inefficient to load or store a datum that spans quad-word boundaries, and virtual memory is trickier when a datum spans two pages. The compiler inserts gaps.
  • Specific cases: 1 byte (char): no restriction. 2 bytes (short): the lowest bit of the address must be 0. 4 bytes (int, float): the lowest 2 bits must be 00. 8 bytes (double, long, char *): the lowest 3 bits must be 000. 16 bytes (long double, GCC/Linux): the lowest 4 bits must be 0000.
  • Within a struct every element's alignment must be satisfied. Overall, each struct has an alignment requirement K = the largest alignment of any element, and both its starting address and its length must be multiples of K. struct S2 { double v; int i[2]; char c; } has v at 0, i at 8, c at 16, then 7 bytes of padding, for 24. An array S2 a[10] has elements at a+0, a+24, a+48, …
  • Array of structs: struct S3 { short i; float v; short j; } a[10]; is 12 bytes (i at 0, v at 4, j at 8). a[idx] is at a + 12·idx, and j is at offset 8 (the assembler gives a+8, resolved during linking). short get_j(int idx) { return a[idx].j; } becomes leaq (%rdi,%rdi,2),%rax (3·idx); movzwl a+8(,%rax,4),%eax.
  • Saving space: put large data types first. struct S4 { char c; int i; char d; } is 12 bytes (c, 3 pad, i, d, 3 pad); struct S5 { int i; char c; char d; } is 8 bytes (i, c, d, 2 pad). K = 4 in both.
  • Unions: allocated according to the largest element, and only one field can be used at a time. union U1 { char c; int i[2]; double v; } *up; is 8 bytes (all fields at up+0). The same fields as struct S1 occupy sp+0 … sp+24.
  • Bit patterns through a union: typedef union { float f; unsigned u; } bit_float_t;. float bit2float(unsigned u) { bit_float_t arg; arg.u = u; return arg.f; } is not the same as (float)u. Likewise float2bit is not the same as (unsigned)f. The union reinterprets the bits; a cast converts the value.
  • Byte ordering: short/long/quad words are stored as 2/4/8 consecutive bytes. Big endian (most significant byte at the lowest address; SPARC); little endian (least significant byte at the lowest address; Intel x86, ARM on Android and iOS); bi-endian (configurable; ARM). This can cause problems when binary data is exchanged between machines.
  • Floating point history: x87 FP (legacy, "very ugly"), then SSE FP (SIMD, on x86 since the 2000s; a special use of the vector instructions), then AVX (the newest, similar to SSE, documented in the book).
  • XMM registers: 16 in total, 16 bytes each. One can hold 16 single-byte integers, 8 16-bit integers, 4 32-bit integers, 4 floats, 2 doubles, 1 float or 1 double. Scalar ops: addss %xmm0,%xmm1 (single precision), addsd (double). SIMD: addps (4 singles in parallel).
  • FP basics: arguments in %xmm0, %xmm1, …; result in %xmm0; all XMM registers caller-saved. float fadd(float x, float y) becomes addss %xmm1,%xmm0; ret. double dadd becomes addsd %xmm1,%xmm0; ret.
  • FP memory referencing: integer and pointer arguments are still passed in the regular registers. dincr: double dincr(double *p, double v) { double x = *p; *p = x + v; return x; } becomes movapd %xmm0,%xmm1 (copy v); movsd (%rdi),%xmm0 (x = *p); addsd %xmm0,%xmm1 (t = x + v); movsd %xmm1,(%rdi) (*p = t); ret.
  • Other FP aspects: lots of instructions in different formats; comparisons with ucomiss/ucomisd, which set CF, ZF and PF; constants: xorpd %xmm0,%xmm0 sets zero, and others are loaded from memory.
  • Summary: arrays are contiguous, use index arithmetic, and have no bounds checking. Structs are packed in a single region, accessed with compiler-determined offsets, and may need internal and external padding. Unions share storage. FP data lives in XMM registers.

The method, step by step (what the instructor draws)

  1. Map the registers to variables first. Underline the prototype parameters and write "xp → %rdi, yp → %rsi, zp → %rdx". On a problem like 3.2 the register table is on the slide, and the instructor circles the register to read its size (%eax → 4 bytes → l; %dx → 2 → w).

  3. Name the intermediates to match the C blanks (T1 = x | y, T2 = T1 >> 3, T3 = ~T2, then rax = z, t4 = z − T3).
  4. For dereferences, draw arrows. For 3.5 (decode1) the instructor drew *xp/*yp/*zp → (%rdi)/(%rsi)/(%rdx) → %r8/%rcx/%rax → x, y, z, then the stores x → *yp, y → *zp, z → *xp.
  5. For control flow, write the condition on each edge. For 3.18 the arrows were labelled "x < −3" on the fall-through and "x ≥ −3" on the jump to .L2, "y < z" / "y ≥ z" for the inner if, and "x > 2" at .L2. Then the arrows connect each block back to its blank in the C template, and the final C is written in a box.
  6. For loops, circle the backward jump (the loop) and draw the forward jmp to the test (jump-to-middle) in a different colour, as on the 3.24 slide.
  7. Tables (3.1, 3.6, 3.8): fill them row by row, computing the address explicitly for each memory operand.
Takeaway. On the quiz, write the annotations next to the assembly before you write any C. Most marks are lost by skipping this step (getting the sub order wrong, the negated branch condition wrong, or missing a register reuse).

Problem 22 [3.35] — rfun (recursion)

rfun:                  # x in %rdi
  pushq %rbx
  movq  %rdi, %rbx     # save x in a callee-saved register
  movl  $0, %eax
  testq %rdi, %rdi
  je    .L2            # if x == 0 return 0
  shrq  $2, %rdi       # nx = x >> 2
  call  rfun
  addq  %rbx, %rax     # x + rv
.L2:
  popq  %rbx
  ret

A. %rbx holds the parameter x, so it is still available to compute the result after the recursive call. B. if (x == 0) return 0; unsigned long nx = x >> 2; long rv = rfun(nx); return x + rv;

Note: here the push happens before the base-case test, so .L2 must pop as well. Compare pcount_r, which pushes only on the recursive path.

F. Traps and common mistakes

  1. Operand order: AT&T is src, dst. subq %rdi,%rax is rax − rdi. cmpq %rsi,%rdi compares rdi to rsi (rdi − rsi).
  2. Negated branches: the assembly jumps when the C condition is false (to skip the then-block).
  3. Decimal vs hex displacements: 260(%rcx,%rdx) is decimal 260 = 0x104.
  4. $ vs no $: $0x108 is the number 0x108. 0x108 is the memory at address 0x108.
  5. leaq never reads memory and never sets flags.
  6. 32-bit writes zero the upper half; 8- and 16-bit writes do not. movl $0,%eax clears all of %rax.
  7. Signed vs unsigned: sar vs shr; g/l vs a/b; movs vs movz. Extension follows the source type.
  8. Pointers are 8 bytes whatever they point to (short **U[6] is 48 bytes).
  9. Pointer arithmetic scales: S+1 for short* is +2 bytes, not +1.
  10. Switch: remember the offset subtraction; repeated table entries = shared cases; entries equal to the default label = missing cases.
  11. do-while runs at least once; while may run zero times.
  12. Register reuse: the compiler recycles registers (%rdx was z, then t4, in arith). Track what each register holds now.
  13. Caller- vs callee-saved: a value needed after a call must be in a callee-saved register or on the stack. A function that uses %rbx must push and pop it.
  14. Return address = the address of the instruction after the call (call address + call length).
  15. Struct size must be a multiple of the largest field alignment (end padding).
  16. Nested vs multi-level arrays look the same in C but need 1 vs 2 memory reads.
  17. Union vs cast: reading another union field reinterprets the bits; a cast converts the value.
  18. notq is ~ (bitwise NOT); negq is − (two's-complement negation).
  19. One-operand shifts (shrq %rdi) shift by 1.

H. Glossary

ISAInstruction set architecture: the programmer-visible contract (instructions, registers, memory model).
MicroarchitectureThe implementation of an ISA (caches, frequency, pipeline).
CISC / RISCComplex vs reduced instruction set computer. x86 is CISC.
PC / %ripProgram counter: the address of the next instruction.
Effective addressThe address computed by D(Rb,Ri,S).
Condition codesThe CF, ZF, SF, OF flags set by the last arithmetic/logic/cmp/test.
Jump tableAn array of code addresses used by switch for an indirect jump.
Jump-to-middleWhile-loop translation that jumps to the test first (-Og).
Guarded-doWhile-loop translation: an initial test, then a do-while (-O1).
Stack frameThe stack region for one procedure call: saved registers, locals, argument build area.
Caller-/callee-savedWho is responsible for preserving a register's value across a call.
ReentrantCode that can have several active instances at once (needed for recursion).
Row-major2-D array layout: rows stored one after another.
AlignmentThe requirement that a K-byte object start at an address that is a multiple of K.
EndiannessThe byte order of multi-byte values in memory. x86 is little endian.
SIMDSingle instruction, multiple data (packed XMM operations).
-Og / -O1GCC optimisation levels: -Og is debug-friendly basic optimisation, -O1 is more aggressive. They produce different loop forms.
