1. The big picture

A C program is turned into something the CPU can run in four steps:

p1.c ──(compiler: gcc -Og -S)──▶ p1.s ──(assembler: as)──▶ p1.o
     ──(linker: ld + static libraries .a)──▶ p (executable)

objdump -d p   ◀── the disassembler goes back from bytes to assembly
  • ISA (architecture) = the part of the processor design an assembly programmer sees: the instructions, the registers and the memory model. Examples: x86-64 (Intel/AMD), ARM (phones).
  • Microarchitecture = how the ISA is built: cache sizes, clock frequency, pipelines. It is invisible to the assembly code.
  • Machine code = bytes. Assembly = a readable text version of those bytes. x86 instructions vary in length (1 to 15 bytes), and x86 is a CISC design (many complex instructions), unlike RISC.
  • The state the programmer can see: the PC (%rip, the address of the next instruction), 16 integer registers, the condition codes (CF, ZF, SF, OF) and memory (one big byte array that holds code, data and the stack).
  • Assembly has no types and no variables. "Integers" are 1, 2, 4 or 8 bytes, addresses are just 8-byte integers, and arrays and structs are just runs of bytes in memory.
Why learn this? The lecture gives three reasons: to see what the compiler does and what it can optimise, to understand how programs behave at run time, and to understand vulnerabilities such as buffer overflows.

Important rule. Writing a 32-bit register (e.g. movl, addl to %eax) zeroes the upper 32 bits of the 64-bit register. Writing an 8-bit or 16-bit register leaves the other bytes unchanged. This is why the compiler writes movl $0, %eax to clear all of %rax, and why there is no movzlq instruction.

The old names explain the letters: a = accumulator, c = counter, d = data, b = base, si/di = source/destination index, sp = stack pointer, bp = base pointer.

3. Operands and addressing modes

There are three kinds of operand:

  • Immediate: $0x400, $-533. A constant. The $ is required. It can never be a destination.
  • Register: %rax. Its contents.
  • Memory: anything in parentheses, or a bare number like 0x104 (an absolute address). It means "the bytes at this address".

The general memory form is D(Rb,Ri,S), which means Mem[ Rb + S·Ri + D ]:

  • D: a constant displacement (can be negative, often hex).
  • Rb: the base register (any of the 16).
  • Ri: the index register (any except %rsp).
  • S: the scale, which must be 1, 2, 4 or 8 (the sizes of the data types).

Any part can be left out: (Rb), D(Rb), (Rb,Ri), (,Ri,S), D(,Ri,S).

Worked example (in the style of Practice Problem 3.1)

Let %rdx = 0xf000 and %rcx = 0x0100.

ExpressionComputationAddress
0x8(%rdx)0xf000 + 0x80xf008
(%rdx,%rcx)0xf000 + 0x1000xf100
(%rdx,%rcx,4)0xf000 + 4·0x1000xf400
0x80(,%rdx,2)2·0xf000 + 0x800x1e080

Method: (1) compute the address in hex, (2) look the address up in the memory table, (3) that value is the operand's value. A $ means no lookup. A bare number means you do look it up.

Try it. %rax = 0x100 and %rcx = 1, and M[0x104] = 0xAB and M[0x108] = 0x13. What is (a) 4(%rax)? (b) $0x108? (c) 0x104? (d) (%rax,%rcx,4)?

Answers: (a) 0xAB (b) 0x108 (c) 0xAB (d) address 0x104, so 0xAB.

4. mov, suffixes and extension

movq Source, Dest copies Source into Dest. AT&T syntax always reads as source first, destination second.

SuffixSizeC type
b1 bytechar
w2 bytes ("word")short
l4 bytes ("long word")int, float*
q8 bytes ("quad")long, pointers, double*

* float and double use different (XMM) instructions; the size is what matters here.

Allowed combinations: Imm→Reg, Imm→Mem, Reg→Reg, Reg→Mem, Mem→Reg. Not Mem→Mem: you have to go through a register.

How to pick the suffix

Look at the register operand that is not inside an address (%eax → l, %dx → w, %bl → b, %rax → q). Registers inside parentheses are addresses and are always 64-bit, so they tell you nothing about the data size.

movl %eax, (%rsp)          movw (%rax), %dx          movb $0xFF, %bl
movb (%rsp,%rdx,4), %dl    movq (%rdx), %rax         movw %dx, (%rax)

Zero and sign extension (going from a smaller type to a bigger one)

  • movzSD: zero-extend from source size S to destination size D. Examples: movzbw, movzbl, movzwl, movzbq, movzwq.
  • movsSD: sign-extend (copy the sign bit). Examples: movsbw, movsbl, movswl, movsbq, movswq, movslq. cltq is short for movslq %eax,%rax.

  3. Same size: plain mov.

  • The shift amount is an immediate or %cl.
  • add, sub and imul are the same instruction for signed and unsigned numbers, because two's-complement arithmetic produces the same bits either way. The difference shows up only in shifts (sar vs shr), in comparisons (which flags you test) and in division.
  • cqto sign-extends %rax into %rdx:%rax, and idivq S divides that 128-bit number by S, giving the quotient in %rax and the remainder in %rdx. You see this in the switch lecture's w = y/z.

leaq: "load effective address"

leaq D(Rb,Ri,S), Dst stores the address D + Rb + S·Ri in Dst and never touches memory. It has two uses:

  1. Pointers: p = &x[i] becomes leaq (%rdi,%rsi,4),%rax.
  2. Cheap arithmetic of the form x + k·y + c with k ∈ {1,2,4,8}. leaq does not set the condition codes.
Instruction (%rax = x, %rcx = y)%rdx =
leaq 6(%rax), %rdxx + 6
leaq (%rax,%rcx), %rdxx + y
leaq (%rax,%rcx,4), %rdxx + 4y
leaq 7(%rax,%rax,8), %rdx9x + 7
leaq 0xA(,%rcx,4), %rdx4y + 10
leaq 9(%rax,%rcx,2), %rdxx + 2y + 9

Multiplying by constants without imul

long m12(long x) { return x*12; }
  leaq (%rdi,%rdi,2), %rax    # t = x + 2x = 3x
  salq $2, %rax               # t << 2 = 12x

Common patterns: 3x = (r,r,2), 5x = (r,r,4), 9x = (r,r,8). Then salq $k multiplies by 2k. leaq (,%rdi,8),%rdx ; subq %rdi,%rdx gives 8x − x = 7x (from the L14 example).

6. Reverse-engineering arithmetic: the core skill

Almost every quiz question is "here is the assembly, write the C". The instructor's method in the revision video is:

  1. Write down which C variable is in which register at the start (args: %rdi, %rsi, %rdx, …).
  2. Go line by line and write next to each one what the destination register now holds, as a C expression of the original variables.
  3. Give each intermediate result a name (t1, t2, …) matching the blanks in the C template.
  4. Watch the operand order of sub: subq A, B means B − A.

Worked example: arith (lecture L10)

long arith(long x, long y, long z) {
  long t1 = x + y;
  long t2 = z + t1;
  long t3 = x + 4;
  long t4 = y * 48;
  long t5 = t3 + t4;
  long rval = t2 * t5;
  return rval;
}
arith:
  leaq (%rdi,%rsi), %rax      # t1 = x+y
  addq %rdx, %rax             # t2 = t1+z
  leaq (%rsi,%rsi,2), %rdx    # 3y
  salq $4, %rdx               # t4 = 48y
  leaq 4(%rdi,%rdx), %rcx     # t5 = x+4+t4
  imulq %rcx, %rax            # rval = t2*t5
  ret

Notice that the compiler merged t3 = x + 4 into the leaq for t5, and reused %rdx (z is no longer needed after line 2). Registers get recycled, so always track what each register holds now.

Worked example: Practice Problem 3.10 (arith2)

orq  %rsi, %rdi     # rdi = x | y            → t1 = x | y
sarq $3, %rdi       # rdi = t1 >> 3           → t2 = t1 >> 3
notq %rdi           # rdi = ~t2              → t3 = ~t2
movq %rdx, %rax     # rax = z
subq %rdi, %rax     # rax = z - t3           → t4 = z - t3

Worked example: Practice Problem 3.5 (decode1)

movq (%rdi), %r8    # x = *xp
movq (%rsi), %rcx   # y = *yp
movq (%rdx), %rax   # z = *zp
movq %r8, (%rsi)    # *yp = x
movq %rcx, (%rdx)   # *zp = y
movq %rax, (%rdi)   # *xp = z

So the C is long x=*xp, y=*yp, z=*zp; *yp=x; *zp=y; *xp=z;, which rotates the three values. Parentheses around a register mean dereference: (%rdi) is *xp.

xorq %rdx,%rdx (Practice Problem 3.11)

x ^ x = 0, so this sets %rdx to 0. It is the compiler's idiom for zeroing a register. The obvious alternative is movq $0,%rdx, but the xor form takes fewer bytes to encode (3 bytes vs 7; xorl %edx,%edx is even shorter at 2 bytes and also clears the upper half).

7. Condition codes

There are four 1-bit flags, set as a side effect of arithmetic and logic instructions (but not leaq):

FlagMeaning after t = a + b (or a − b)
CF (carry)a carry/borrow out of the top bit, i.e. unsigned overflow
ZF (zero)t == 0
SF (sign)t < 0 (top bit is 1)
OF (overflow)signed overflow: pos + pos → neg, or neg + neg → non-negative
  • cmpq b, a computes a − b, sets the flags and throws the result away. The order is reversed: "cmpq %rsi,%rdi" compares rdi (a) with rsi (b).
  • testq b, a computes a & b and sets ZF and SF. testq %rax,%rax is the idiom for "is rax zero / negative / positive?".
  • setX D sets one byte to 0 or 1 based on the flags. The usual pattern is setX %al followed by movzbl %al,%eax.
Suffix XCondition (after cmp b,a)FlagsKind
e / nea == b / a != bZF / ~ZFany
s / nsresult negative / non-negativeSF / ~SFany
ga > b~(SF^OF) & ~ZFsigned
gea ≥ b~(SF^OF)signed
la < bSF^OFsigned
lea ≤ b(SF^OF) | ZFsigned
aa > b~CF & ~ZFunsigned
aea ≥ b~CFunsigned
ba < bCFunsigned
bea ≤ bCF | ZFunsigned
Memory aid. Greater/Less are for signed numbers. Above/Below are for unsigned numbers. Why SF^OF for "less"? If there was no overflow, the sign of a − b tells you the answer directly. If there was an overflow, the sign is flipped, so XOR with OF corrects it.

Worked example

int gt(long x, long y) { return x > y; }
  cmpq  %rsi, %rdi     # compare x : y   (computes x - y)
  setg  %al            # al = (x > y)
  movzbl %al, %eax     # zero the rest of %rax
  ret

8. Jumps, if/else and the "goto" style

jmp L always jumps. jX L jumps when condition X holds (same suffixes as setX). jmp *Operand is an indirect jump that takes its target from a register or from memory (used for switch).

The compiler turns if (Test) Then else Else into:

    ntest = !Test;  if (ntest) goto Else;
    Then;  goto Done;
Else:
    Else;
Done:
Key fact for reading assembly. The conditional jump usually tests the opposite of the C condition, because it jumps past the then-block. If you see cmpq %rsi,%rdi ; jle .L4, the code that falls through is the x > y case.

Worked example: absdiff

long absdiff(long x, long y) {
  long result;
  if (x > y) result = x - y;
  else       result = y - x;
  return result;
}
absdiff:
  cmpq %rsi, %rdi     # x : y
  jle  .L4            # if x <= y goto Else
  movq %rdi, %rax
  subq %rsi, %rax     # x - y
  ret
.L4:
  movq %rsi, %rax
  subq %rdi, %rax     # y - x
  ret

Worked example: Practice Problem 3.18 (nested if) — the revision video's main example

test:                          # x in rdi, y in rsi, z in rdx
  leaq  (%rdi,%rsi), %rax      # rax = x+y
  addq  %rdx, %rax             # rax = x+y+z     ← initial val
  cmpq  $-3, %rdi
  jge   .L2                    # x >= -3 → .L2   so the block is x < -3
  cmpq  %rdx, %rsi
  jge   .L3                    # y >= z → .L3    so inner then is y < z
  movq  %rdi, %rax
  imulq %rsi, %rax             # val = x*y
  ret
.L3:
  movq  %rsi, %rax
  imulq %rdx, %rax             # val = y*z
  ret
.L2:
  cmpq  $2, %rdi
  jle   .L4                    # x <= 2 → skip   so else-if is x > 2
  movq  %rdi, %rax
  imulq %rdx, %rax             # val = x*z
.L4:
  rep; ret
long test(long x, long y, long z) {
  long val = x + y + z;
  if (x < -3) {
    if (y < z)
      val = x * y;
    else
      val = y * z;
  } else if (x > 2)
    val = x * z;
  return val;
}

Practice Problem 3.16: why does one if produce two branches?

if (p && a > *p) *p = a; compiles to testq %rsi,%rsi ; je .L1 ; cmpq %rdi,(%rsi) ; jge .L1 ; movq %rdi,(%rsi). Because && short-circuits, each part of the condition gets its own jump. If p is null, the code skips the test of a > *p entirely (and never dereferences null). In goto form: if (p == 0) goto done; if (*p >= a) goto done; *p = a; done: return;

9. Conditional moves

cmovX S, D means: if condition X holds, D = S. The compiler computes both outcomes, then picks one without branching:

result = Then_Expr;   eval = Else_Expr;   nt = !Test;   if (nt) result = eval;
absdiff (cmov version):
  movq   %rdi, %rax
  subq   %rsi, %rax     # result = x-y
  movq   %rsi, %rdx
  subq   %rdi, %rdx     # eval = y-x
  cmpq   %rsi, %rdi     # x : y
  cmovle %rdx, %rax     # if x<=y, result = eval
  ret

Why use cmov? A branch the CPU guesses wrong flushes the pipeline, which is slow. A cmov has no jump at all.

When the compiler will not use cmov (both sides are always evaluated):

  • expensive computations: Test ? Hard1(x) : Hard2(x)
  • risky computations: p ? *p : 0 (null dereference)
  • side effects: x > 0 ? x*=7 : x+=3

Practice Problem 3.21 (cmov + branch)

test:  leaq 0(,%rdi,8),%rax   # val = 8x
       testq %rsi,%rsi ; jle .L2          # if y <= 0 goto .L2  → block is y > 0
       movq %rsi,%rax ; subq %rdi,%rax     # rax = y - x
       movq %rdi,%rdx ; andq %rsi,%rdx     # rdx = x & y
       cmpq %rsi,%rdi ; cmovge %rdx,%rax   # if x >= y, rax = x & y
       ret
.L2:   addq %rsi,%rdi ; cmpq $-2,%rsi ; cmovle %rdi,%rax   # if y <= -2, val = x+y
       ret

C: val = 8*x; if (y > 0) { if (x < y) val = y - x; else val = x & y; } else if (y <= -2) val = x + y;

Practice Problem 3.20: division by a power of 2

leaq 7(%rdi),%rax ; testq %rdi,%rdi ; cmovns %rdi,%rax ; sarq $3,%rax     →  x / 8

A right shift rounds down, but C division rounds toward 0. For negative x the code adds a bias of 2k−1 (= 7) before shifting. cmovns keeps plain x when x ≥ 0.

Worked example: popcount, do-while (lecture)

long pcount_do(unsigned long x) {
  long result = 0;
  do {
    result += x & 0x1;
    x >>= 1;
  } while (x);
  return result;
}
  movl $0, %eax       # result = 0
.L2:
  movq %rdi, %rdx
  andl $1, %edx       # t = x & 1
  addq %rdx, %rax     # result += t
  shrq %rdi           # x >>= 1 (sets ZF!)
  jne  .L2            # if (x) goto loop
  rep; ret

Notice: shrq sets ZF, so jne needs no separate test. It uses shr (logical) because x is unsigned.

Worked example: Practice Problem 3.24, jump-to-middle

  movl $1, %eax          # result = 1

long loop_while(long a, long b) {
  long result = 1;
  while (a < b) {
    result = result * (a + b);
    a = a + 1;
  }
  return result;
}

long loop_while2(long a, long b) {
  long result = b;
  while (b > 0) {
    result = result * a;
    b = b - a;
  }
  return result;
}

Spotting tricks the optimiser plays (Practice Problems 3.23, 3.28)

  • Pointers optimised away. In 3.23, long *p = &x; … (*p)++;. Because p always points to x, the compiler does x += y + 1 with a single leaq 1(%rcx,%rax),%rax and keeps x, y, n in registers (%rax, %rcx, %rdx).
  • Guard removed. In 3.28, for (i = 64; i != 0; i--). The compiler knows 64 ≠ 0, so there is no initial test and no jump to the middle; it looks like a plain do-while.
  • English description questions: 3.26 computes the parity of x (val ^= x on each shift, return val & 1). 3.28 reverses the bits of x (val = (val << 1) | (x & 1); x >>= 1).

11. Switch statements and jump tables

For dense case values, GCC builds a jump table: an array of 8-byte code addresses in .rodata. It then does one indirect jump: jmp *.L4(,%rdi,8), which means goto *JTab[x].

long switch_eg(long x, long y, long z) {
  long w = 1;
  switch (x) {
  case 1:  w = y*z;  break;
  case 2:  w = y/z;  /* fall through */
  case 3:  w += z;   break;
  case 5:
  case 6:  w -= z;   break;
  default: w = 2;
  }
  return w;
}
switch_eg:
  movq %rdx, %rcx
  cmpq $6, %rdi          # x : 6
  ja   .L8               # x > 6 or x < 0 → default
  jmp  *.L4(,%rdi,8)     # goto *JTab[x]
.L4:  .quad .L8   # 0  default
      .quad .L3   # 1
      .quad .L5   # 2
      .quad .L9   # 3
      .quad .L8   # 4  missing → default
      .quad .L7   # 5
      .quad .L7   # 6  shared with 5
Recipe for "fill in the switch" questions (Practice Problem 3.31).
  1. Find the smallest case: if there is a subq $k,%rdi (or leaq -k(%rdi)), table index i means case i + k. Without it, the index is the case value.
  2. Find the largest case: the constant in cmpq $n is the largest index, so the largest case is n + k.
  3. ja goes to the default label. Table entries that point to the default label are missing case values.
  4. Several entries pointing to the same label are shared cases (case 5: case 6:).
  5. A block that ends with no jmp/ret and runs into the next block is a fall-through.
  6. Translate each block's instructions into C.

Practice Problem 3.31 solution, for reference: case 5: c = b ^ 15; /* fall through */ case 0: val = c + 112; break; case 2: case 7: val = (c + b) << 2; break; case 4: val = a; break; default: val = b;.

Why ja and not jg? Treating x as unsigned makes negative x a huge number, so one comparison catches both x < 0 and x > max. Why scale 8? Each table entry is an 8-byte address.

12. The stack, call and ret

  • The stack is a region of memory that grows toward lower addresses. %rsp holds the address of the top element (the lowest address in use).
  • pushq Src: %rsp −= 8, then M[%rsp] = Src.
  • popq Dest: Dest = M[%rsp], then %rsp += 8. Dest must be a register.
  • call Label: push the return address (the address of the instruction right after the call), then %rip = Label.
  • ret: pop the return address into %rip.

Worked example: multstore → mult2 (lecture)

400544: callq 400550 <mult2>      before: %rsp = 0x120, %rip = 0x400544
400549: mov %rax,(%rbx)

after call:  %rsp = 0x118, M[0x118] = 0x400549, %rip = 0x400550
in mult2:    400550 mov %rdi,%rax ; 400553 imul %rsi,%rax ; 400557 retq
after ret:   %rsp = 0x120, %rip = 0x400549

Check: the call moves %rsp down by exactly 8 (0x120 → 0x118), and ret moves it back up by 8.

13. Calling conventions and register saving

WhatWhere
Integer/pointer args 1–6%rdi, %rsi, %rdx, %rcx, %r8, %r9

Return value%rax (FP results: %xmm0)
FP args%xmm0, %xmm1, … (a separate count from the integer args)
Caller-saved%rax, %rdi, %rsi, %rdx, %rcx, %r8, %r9, %r10, %r11 (and all %xmm). The callee may overwrite them, so the caller must save them itself if it still needs them after the call.
Callee-saved%rbx, %rbp, %r12, %r13, %r14, %r15 (and %rsp is restored). A function that uses one must push it on entry and pop it before returning.
The lecture's main/fun1 story. main puts x in %rdi and y in %rsi and calls fun1. But fun1 needs %rdi and %rsi for its own calls, so they will be overwritten. If main needs x and y after the call ("make sure x and y are safe!"), it keeps them in callee-saved registers such as %rbx and %r12 (or on the stack).

Worked example: call_incr2 (lecture)

long call_incr2(long x) { long v1 = 15213; long v2 = incr(&v1, 3000); return x + v2; }

call_incr2:
  pushq %rbx               # save the caller's %rbx (callee-saved)
  subq  $16, %rsp          # room for v1
  movq  %rdi, %rbx         # keep x safe across the call
  movq  $15213, 8(%rsp)    # v1 on the stack (its address is taken)
  movl  $3000, %esi
  leaq  8(%rsp), %rdi      # &v1
  call  incr
  addq  %rbx, %rax         # x + v2
  addq  $16, %rsp
  popq  %rbx               # restore
  ret

Practice Problem 3.35 (rfun) asks "what is in %rbx?". The answer is the parameter x, kept so that it can be used after the recursive call returns.

14. Stack frames, locals and recursion

Each active call gets its own frame. From the caller's side (higher addresses) down to the top of the stack:

  ┌──────────────────────┐  higher addresses
  │ caller's frame …      │
  │ args 7+ for this call │
  │ return address        │  ← pushed by call
  ├──────────────────────┤  ← start of the current frame
  │ old %rbp (optional)   │
  │ saved registers       │  (callee-saved ones this function uses)
  │ local variables       │  (only if they cannot live in registers)
  │ argument build area   │  (args 7+ for functions it calls)
  └──────────────────────┘  ← %rsp   lower addresses

A local variable goes on the stack when: there are not enough registers, its address is taken (&v1), or it is an array or struct.

Worked example: recursive popcount (lecture)

long pcount_r(unsigned long x) {
  if (x == 0) return 0;
  else return (x & 1) + pcount_r(x >> 1);
}
pcount_r:
  movl  $0, %eax
  testq %rdi, %rdi
  je    .L6             # base case returns 0
  pushq %rbx            # save the caller's rbx
  movq  %rdi, %rbx
  andl  $1, %ebx        # rbx = x & 1 (survives the call)
  shrq  %rdi            # arg = x >> 1
  call  pcount_r
  addq  %rbx, %rax      # (x&1) + result
  popq  %rbx
.L6:
  rep; ret

Trace for x = 0110₂ (6): rbx values 0, 1, 1 are pushed down the chain. The innermost call returns 0, then the returns add up 0+1 = 1, 1+1 = 2, 2+0 = 2. Recursion needs nothing special: each call has its own frame, and the register conventions protect each level's data (the stack is LIFO).

15.2 Nested (multi-dimensional) arrays

T A[R][C]; has R rows of C elements each, R·C·K bytes in total (K = sizeof(T)), stored in row-major order (all of row 0, then all of row 1, …).

The two formulas to memorise.
Row: A[i] starts at A + i·C·K.
Element: &A[i][j] = A + (i·C + j)·K.
Only C (the number of columns) appears. R is never needed to find an address.

Example: in a 3×3 matrix, a[1][2] → 1·3 + 2 = flat index 5. If each element is k bytes, that is Mem[a + 5k].

int pgh[4][5];      /* zip_dig pgh[4] */
int *get_pgh_zip(int index) { return pgh[index]; }        # a row
  leaq (%rdi,%rdi,4), %rax       # 5*index
  leaq pgh(,%rax,4), %rax        # pgh + 20*index

int get_pgh_digit(int index, int dig) { return pgh[index][dig]; }
  leaq (%rdi,%rdi,4), %rax       # 5*index
  addl %rax, %rsi                # 5*index + dig
  movl pgh(,%rsi,4), %eax        # M[pgh + 4*(5*index + dig)]

15.4 Fixed vs variable-size matrices

#define N 16
int fix_ele(fix_matrix a, size_t i, size_t j) { return a[i][j]; }
  salq $6, %rsi                  # 64*i   (C*K = 16*4 = 64, so a shift)
  addq %rsi, %rdi                # a + 64i
  movl (%rdi,%rdx,4), %eax       # M[a + 64i + 4j]

int var_ele(size_t n, int a[n][n], size_t i, size_t j) { return a[i][j]; }
  imulq %rdx, %rdi               # n*i   (n unknown at compile time → real multiply)
  leaq (%rsi,%rdi,4), %rax       # a + 4*n*i
  movl (%rax,%rcx,4), %eax       # M[a + 4ni + 4j]

Before variable-length arrays existed in C, programmers wrote a[IDX(n,i,j)] with #define IDX(n,i,j) ((i)*(n)+(j)), the same formula done by hand.

15.5 Reverse-engineering M and N (the lecture's final example)

long A[M][N];
long B[N][M];
long sum_element(int i, int j) {
  return A[i][j] + B[j][i];
}
leaq (,%rdi,8), %rdx       # rdx = 8i
subq %rdi, %rdx            # rdx = 7i
addq %rsi, %rdx            # rdx = 7i + j        → A's row length N = 7
leaq (%rsi,%rsi,4), %rax   # rax = 5j
addq %rax, %rdi            # rdi = 5j + i        → B's row length M = 5
movq B(,%rdi,8), %rax      # M[B + 8(5j + i)]
addq A(,%rdx,8), %rax      # + M[A + 8(7i + j)]
ret

Answer: M = 5, N = 7. Method: find the index expression multiplying i for A (that is A's column count N) and the one multiplying j for B (that is B's column count M).

16. Structures and alignment

A struct is one block of memory with its fields in declaration order. The compiler fixes each field's offset at compile time, and the machine code just uses those offsets.

struct rec { int a[4]; size_t i; struct rec *next; };
/* offsets: a 0, i 16, next 24; size 32 */
int *get_ap(struct rec *r, size_t idx) { return &r->a[idx]; }
  leaq (%rdi,%rsi,4), %rax       # r + 4*idx

void set_val(struct rec *r, int val) {
  while (r) { int i = r->i; r->a[i] = val; r = r->next; }
}
.L11:
  movslq 16(%rdi), %rax          # i = M[r+16]
  movl   %esi, (%rdi,%rax,4)     # M[r + 4*i] = val
  movq   24(%rdi), %rdi          # r = M[r+24]
  testq  %rdi, %rdi              # test r
  jne    .L11                    # if != 0 goto loop

Alignment rules (x86-64)

  • A primitive of K bytes must sit at an address that is a multiple of K: char any address, short even addresses, int/float multiples of 4, long/double/pointer multiples of 8, long double multiples of 16.
  • Inside a struct, the compiler inserts padding so that every field is aligned.
  • The struct's own alignment K is the largest alignment of any field. The total size is rounded up to a multiple of K (end padding), so that every element of an array of structs is aligned.
  • Why align? Memory is accessed in aligned 4- or 8-byte chunks. A value that crosses a chunk (or page) boundary is slower and trickier for virtual memory.

17. Unions, byte order and floating point

  • Union: all fields start at offset 0 and share the same bytes. Its size is that of the largest member (rounded to its alignment). Only one field is meaningful at a time. union { int i[2]; double v; } is 8 bytes, while the same fields in a struct take 16.
  • Viewing bit patterns: union { float f; unsigned u; }. Writing u and reading f reinterprets the bits. That is not the same as (float)u, which converts the value.
  • Endianness: little endian (x86, ARM in Android/iOS) stores the least significant byte at the lowest address. Big endian (SPARC) stores the most significant byte first. Bi-endian chips (ARM) can do either. 0x12345678 at 0x100 is stored as 78 56 34 12 on little endian.
  • Floating point uses the SSE/AVX XMM registers: 16 of them (%xmm0–%xmm15), 16 bytes each. A register can hold 4 floats, 2 doubles, or a single scalar float/double.
    • Scalar vs SIMD: addss (1 float), addsd (1 double), addps (4 floats at once, "packed").
    • Args in %xmm0, %xmm1, …; result in %xmm0; all XMM registers are caller-saved. Integer and pointer args still use %rdi, … .
    • movsd (%rdi),%xmm0 loads a double; movapd copies between XMM registers; ucomiss/ucomisd compare (setting CF, ZF, PF); xorpd %xmm0,%xmm0 zeroes a register. Other constants are loaded from memory.
double dincr(double *p, double v) { double x = *p; *p = x + v; return x; }
  movapd %xmm0, %xmm1     # copy v
  movsd  (%rdi), %xmm0    # x = *p        (return value goes in xmm0)
  addsd  %xmm0, %xmm1     # t = x + v
  movsd  %xmm1, (%rdi)    # *p = t
  ret

18. One-page cheat sheet

Operands

$c constant · %r register · D(Rb,Ri,S) = M[D + Rb + S·Ri], S ∈ {1,2,4,8}, Ri ≠ %rsp · a bare number is an absolute address.

Sizes

b 1 · w 2 · l 4 · q 8. char 1, short 2, int/float 4, long/double/pointer 8.

Registers

Args: rdi rsi rdx rcx r8 r9 · ret: rax
Callee-saved: rbx rbp r12–r15 (+ rsp)
Caller-saved: rax, the arg registers, r10, r11, all xmm
FP: args xmm0.., return xmm0.
32-bit writes zero the upper half; 8/16-bit writes do not.

Arithmetic

op S,D: D = D op S. subq S,D: D − S. sal/shl = <<; sar = signed >>; shr = unsigned >>. leaq = address math, no memory access, no flags. xor r,r = 0.

Extension

Wider: movz (unsigned source) / movs (signed source). Narrower: load full, store the low part.

Flags

CF unsigned overflow · ZF zero · SF negative · OF signed overflow. cmp b,a → a − b. test b,a → a & b. leaq sets none.

Conditions

e ne s ns · signed: g ge l le · unsigned: a ae b be. Branches jump on the negated C test.

Loops

do-while: test at the bottom only. Jump-to-middle (-Og): jmp test first. Guarded-do (-O1): test before the loop + test at the bottom. for = init; while (test) { body; update; }

Switch

subq $k → min case k. cmpq $n; ja default → max case n + k. jmp *T(,%rdi,8). Entries pointing at default are missing cases; repeated labels are shared cases; no jmp at the end of a block means fall-through.

Stack

push: rsp −= 8, store. pop: load, rsp += 8. call: push the next address, jump. ret: pop into rip. Arg 7 is at 8(%rsp) on entry.

Arrays

&A[i] = A + K·i. &A[i][j] = A + K(i·C + j). Multi-level: M[M[A + 8i] + K·j] (2 reads).

Structs

Field offset is a multiple of its own size; size is a multiple of the largest field. Union size = largest member.
